المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

عندما يتكون نظامك من عدة خدمات خلفية، إجبار العميل (تطبيق الفرونت إند أو الموبايل) على الاتصال بكل خدمة على حدة يسبب تعقيداً في التوثيق ومشاكل CORS وبطء في النقل الشبكي. نمط API Gateway يضع نقطة دخول مركزية موحدة (Single Entry Point) في حافة النظام تتولى توجيه المسارات، إنهاء تشفير SSL، التحقق من التوثيق، وتوزيع الأحمال (Load Balancing) عبر خوارزميات مثل Round Robin.

🤔 سؤال تحدي المهندسين:

ما هو نمط Backend-For-Frontend (BFF Pattern) وما المشكلة التي يحلها؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

هو نمط يتم فيه إنشاء بوابة API مخصصة لكل نوع عميل (بوابة لتطبيق الموبايل ترجع ردوداً خفيفة مدمجة ومضغوطة، وبوابة لتطبيق الويب ترجع بيانات تفصيلية واسعة) بدلاً من بناء API عام واحد ضخم لا يلبي احتياجات أي منهما بكفاءة.

تشريح الكود سطراً بسطر · Code Anatomy

1: # Nginx Reverse Proxy / API Gateway Routing Spec // إعدادات البوابة
2: upstream backend_cluster { server 10.0.0.1; server 10.0.0.2; } // تحديد خوادم الباك إند
3: location /api/v1/auth/ { proxy_pass http://auth_service:3000/; } // توجيه خدمة التوثيق
4: location /api/v1/orders/ { proxy_pass http://orders_service:4000/; } // توجيه خدمة الطلبات

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
ربط كل خدمات الباك إند الداخلية بالإنترنت العام مباشرة دون بوابة API مركزية
✅ الحل الهندسي الصحيح (Best Practice)
عزل جميع الخدمات في شبكة VPC خاصة خلف API Gateway مؤمنة بالكامل

التشخيص الهندسي: فتح الخدمات للعامة يضاعف المساحة المعرضة للهجمات ويجعل تتبع التوثيق مستحيلاً.

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): ما هو نمط Circuit Breaker في بوابات الـ API وفيمَ يفيد؟

هو نمط حماية يمنع الانهيار المتسلسل للنظام (Cascading Failures)؛ عندما تتعطل خدمة داخلية وتفشل 50% من طلباتها، تفتح البوابة قاطع الدائرة (Open Circuit) وترد على المستخدم فوراً برد بديل (Fallback) دون إرسال طلبات للخدمة المتعطلة، مما يمنع تراكم الطلبات المعلقة ويعطي الخدمة وقتاً للتعافي.
