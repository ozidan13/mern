N-Tier Layered Architecture: Controllers, Services, Repositories & DTOs

المعمارية متعددة الطبقات (N-Tier): وحدات التحكم والخدمات والمستودعات والـ DTOs

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم مسؤوليات الطبقات الأربع: Controller (HTTP), Service (Business Logic), Repository (Data Access), DTO (Data Transfer).
  • تطبيق مبدأ المسؤولية الفردية (Single Responsibility Principle) وفصل منطق الأعمال عن بروتوكول HTTP.
  • تسهيل كتابة اختبارات الوحدات (Unit Testing) بمحاكاة طبقة المستودعات بسهولة.

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

في المشاريع المبتدئة، تجد المطور يكتب كل شيء داخل دالة الموجه (Route Handler): فحص الطلب، الاتصال بقاعدة البيانات، حساب الضرائب، إرسال الإيميلات، وتنسيق الرد في 200 سطر متشابك (Fat Controllers)! هذا يسمى Spaghetti Code ويجعل اختبار منطق الأعمال بمعزل عن الـ HTTP مستحيلاً. المعمارية الطبقية (Layered Architecture) تقسم النظام إلى 4 طبقات مستقلة تفصل المسؤوليات بشكل صارم.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
طبقة التحكم (Controller Layer)

تستقبل كائن req وتفحصه عبر DTO وتوجه البيانات للخدمة وتحدد كود حالة الرد res.status().

2
طبقة الأعمال (Service Layer)

تحتوي على كل الحسابات وقواعد العمل (Business Rules) وتعمل كدوال نقية لا تعرف شيئاً عن req أو res.

3
طبقة المستودعات (Repository Layer)

تتولى التحدث المباشر مع قاعدة البيانات (Prisma أو Mongoose) مما يتيح تغيير محرك البيانات دون مساس بطبقة الأعمال.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

لماذا يحظر تماماً تمرير كائني req و res إلى طبقة الـ Service؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لأن تمرير كائنات HTTP يربط منطق الأعمال ببروتوكول الويب ويمنع إعادة استخدام نفس الـ Service مع قنوات أخرى مثل WebSocket Handlers أو Message Queue Workers أو أوامر CLI.

1: // Controller: Only parses HTTP and calls Service // التحكم بالـ HTTP فقط
2: export const register = async (req, res) => { // معالج المسار
3:   const user = await authService.registerUser(req.body); // استدعاء الخدمة
4:   return res.status(201).json({ status: "success", data: user }); // إرسال الرد
5: };                                              // نهاية المعالج

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
كتابة استعلامات SQL أو Prisma داخل ملفات الـ Controllers مباشرة
✅ الحل الهندسي الصحيح (Best Practice)
حصر استعلامات قواعد البيانات داخل طبقة Repository واستدعاؤها عبر Service

التشخيص الهندسي: خلط الاستعلامات مع الـ Controllers يجعل الكود غير قابل للاختبار المعزول (Unit Testing).

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): ما هي كائنات الـ DTOs (Data Transfer Objects) وفيمَ تفيد في المعمارية الطبقية؟

الـ DTOs هي كائنات بسيطة مجردة تحدد شكل ونوع البيانات التي تنتقل بين الطبقات (مثل `CreateUserDTO`)؛ وتفيد في: 1. منع تسريب الحقول الزائدة. 2. التحقق التلقائي من صحة الحقول قبل دخولها للنظام. 3. توفير عقود نوعية (Type Contracts) واضحة بين الواجهة والسيرفر.
