المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

بوستجريس (PostgreSQL) تُلقب بـ "أقوى قاعدة بيانات علائقية مفتوحة المصدر في العالم". قوتها لا تقتصر على الجداول العادية، بل في دعمها لأنواع بيانات متقدمة نادراً ما تجدها في قواعد أخرى: المصفوفات الأصلية (TEXT[])، كائنات الـ JSONB الثنائية فائقة السرعة، المعرفات العالمية (UUIDv7)، والتوقيت الزمني الدقيق مع المناطق الزمنية (TIMESTAMPTZ).

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
القيود على مستوى العمود (Constraints)

استخدام CHECK (price > 0) لضمان عدم دخول قيم غير منطقية لقاعدة البيانات أبداً.

2
المعرفات الموزعة (UUID)

استخدام gen_random_uuid() لتوليد مفاتيح فريدة غير متسلسلة تحمي من هجمات التخمين.

3
التوقيت الموحد (TIMESTAMPTZ)

تخزين الوقت دائماً بصيغة UTC وتحويله تلقائياً للمنطقة الزمنية للعميل عند العرض.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

لماذا يحظر استخدام TIMESTAMP بدون منطقة زمنية (WITHOUT TIME ZONE) في التطبيقات العالمية؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لأن TIMESTAMP بدون منطقة زمنية يتجاهل فارق التوقيت ويحفظ الأرقام فقط، مما يسبب تشوه مواعيد الحجوزات والمعاملات المالية عند تعامل مستخدمين من دول ومناطق زمنية مختلفة.

تشريح الكود سطراً بسطر · Code Anatomy

1: CREATE TABLE products (                         // إنشاء جدول المنتجات
2:   id UUID PRIMARY KEY DEFAULT gen_random_uuid(), // مفتاح أساسي فريد مشفر
3:   price NUMERIC(10, 2) NOT NULL CHECK (price >= 0), // نوع دقيق مالي مع قيد فحص
4:   tags TEXT[] DEFAULT '{}'                      // مصفوفة نصوص مدمجة
5: );                                              // نهاية الجدول

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
price FLOAT; /* استخدام Float للمعاملات المالية يسبب أخطاء تقريب بنكية قاتلة! */
✅ الحل الهندسي الصحيح (Best Practice)
price NUMERIC(12, 2); /* نوع مالي دقيق ثابت الفاصلة بدون أي أخطاء تقريب */

التشخيص الهندسي: النوع Float يعتمد على معيار IEEE 754 غير الدقيق ويسبب اختفاء القروش في الحسابات التراكمية.

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): ما هي ميزة استخدام UUIDv7 الجديد بدلاً من UUIDv4 الكلاسيكي في المفاتيح الأساسية لـ PostgreSQL؟

الـ UUIDv4 عشوائي بالكامل في الذاكرة، مما يسبب تبعثر شجرة الفهرس (B-Tree Fragmentation) وبطء الكتابة في الجداول الضخمة. بينما UUIDv7 يدمج طابعاً زمنياً في بدايته (Time-Ordered)، مما يجعله مرتباً زمنياً تصاعدياً ويوفر سرعة إدخال فائقة مماثلة للمعرفات الرقمية التسلسلية مع الحفاظ على الأمان والفرادة العالمية.
