رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

كيف تستطيع PostgreSQL خدمة آلاف عمليات القراءة والكتابة في نفس اللحظة دون أن يعطل القارئ الكاتب (Readers don't block Writers)? السر يكمن في معمارية MVCC (Multi-Version Concurrency Control) حيث يتم إنشاء إصدارات متعددة من كل صف (Tuples مع xmin و xmax). فهم مستويات العزل (Read Committed, Repeatable Read, Serializable) والأقفال الصريحة (SELECT ... FOR UPDATE) هو مفتاح منع مشاكل حجز التذاكر المزدوج وسحب الأرصدة المتزامن.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

1

معمارية الـ MVCC

كل تعديل ينشئ نسخة جديدة من الصف ويوجه القراء للنسخة المعتمدة وقت بدء استعلامهم دون قفل الجدول.

2

القفل المتشائم (SELECT ... FOR UPDATE)

قفل الصف المالي أو مقعد الحجز حتى اكتمال المعاملة لمنع مستخدم آخر من حجزه في نفس الثانية.

3

التنظيف التلقائي (AutoVACUUM)

حذف النسخ الميتة القديمة (Dead Tuples) وتحرير مساحة الصفحات في الذاكرة والقرص.

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

تحدث عندما تقفل المعاملة A الصف 1 وتطلب الصف 2، بينما تقفل المعاملة B الصف 2 وتطلب الصف 1؛ يرصد محرك PostgreSQL هذا التوقف الدائري تلقائياً عبر deadlock_timeout ويقوم بإلغاء إحدى المعاملتين وإرجاع خطأ Deadlock detected.

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

1: BEGIN;                                            // بدء المعاملة
2: SELECT balance FROM accounts WHERE id = 101 FOR UPDATE; // قفل تشاؤمي حصري على الصف
3: UPDATE accounts SET balance = balance - 50 WHERE id = 101; // تعديل الرصيد بأمان تام
4: COMMIT;                                           // تثبيت التغيير وتحرير القفل

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
const bal = await getBal(); await updateBal(bal - 50); /* ثغرة Race Condition تتيح سحب الرصيد مرتين! */
✅ الحل الهندسي القياسي (Best Practice)
UPDATE accounts SET balance = balance - 50 WHERE id = 101 AND balance >= 50;

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

ما هي وظيفة أمر VACUUM FULL في PostgreSQL ومتى يجب الحذر الشديد عند استخدامه؟

أمر `VACUUM` العادي يعلم على الصفحات الميتة لإعادة استخدامها دون قفل الجداول. أما `VACUUM FULL` فيقوم بإعادة كتابة الجدول بالكامل على القرص لتقليص حجمه وتحرير المساحة لنظام التشغيل، لكنه يأخذ قفلاً حصرياً كاملاً (Exclusive Table Lock) يمنع أي قراءة أو كتابة على الجدول حتى ينتهي، لذا يحظر تشغيله في أوقات الذروة الإنتاجية.
