Advanced Analytical Window Functions: OVER, PARTITION BY, RANK & LEAD/LAG

الدوال التحليلية المتقدمة (Window Functions): جمل OVER، التقسيم بـ PARTITION BY و LEAD/LAG

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم الفرق الجوهري بين دوال التجميع (GROUP BY: تقلص الصفوف) والدوال التحليلية (Window Functions: تحافظ على كل الصفوف).
  • إتقان جملة OVER() وتقسيم النوافذ الحسابية بـ PARTITION BY والترتيب بـ ORDER BY.
  • استخدام دوال الترتيب والتصنيف: ROW_NUMBER(), RANK(), و DENSE_RANK().
  • استخراج قيم الصفوف السابقة والتالية للمقارنة الزمنية باستخدام LEAD() و LAG().

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

في تقارير الأعمال وتحليلات البيانات، يطلب منك المدراء أسئلة مثل: - "اعرض لي كل موظف، مع راتبه، ومتوسط راتب القسم التابع له، وترتيبه داخل قسمه، والفرق بين راتبه وراتب الموظف الذي يسبقه مباشرة"! لو حاولت حل هذه المسألة بـ GROUP BY العادية، ستفشل لأن GROUP BY تقوم بدمج الصفوف وتقليصها إلى صف واحد لكل قسم، وتخفي تفاصيل الموظفين الأفراد! الحل المعماري السحري في SQL هو **الدوال التحليلية (Window Functions)**. الـ Window Functions تجري عمليات حسابية معقدة عبر مجموعة من الصفوف المرتبطة بالصف الحالي (نافذة حسابية Window Frame)، **مع الحفاظ على كافة صفوف الجدول الأصلية كاملة بدون أي تقليص**! في هذا الدرس، هنتعلم إزاي نبني لوحات تحليلات مالية متقدمة، إزاي نستخدم **LEAD** و **LAG** لحساب نسب النمو، ولماذا تعتبر هذه الدوال الأهم في مقابلات العمل لكبار المهندسين.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

01

تشريح جملة OVER (PARTITION BY ... ORDER BY ...)

تقسيم البيانات إلى مجموعات مستقلة (Partitions) وتطبيق الحسابات الرياضية داخل كل قسم مع الاحتفاظ بالصفوف الفردية.

02

الترتيب والتصنيف بـ ROW_NUMBER() و DENSE_RANK()

إعطاء تسلسل فريد لكل صف أو ترتيب مالي دقيق لا يترك فجوات عند تساوي القيم (DENSE_RANK).

03

المقارنة الزمنية ونسب النمو بـ LAG() و LEAD()

الوصول لقيمة الصف السابق (LAG) أو الصف التالي (LEAD) لحساب فارق المبيعات اليومية أو الشهرية بدون أي Self-Join.

04

المجموع التراكمي المتحرك (Running Totals)

حساب الرصيد التراكمي المستمر SUM(amount) OVER (ORDER BY date) عبر مسح النافذة الزمنية تدريجياً.

05

تحديد أفضل N عناصر لكل فئة (Top-N Per Group)

استخدام ROW_NUMBER() داخل CTE لجلب أعلى 3 منتجات مبيعاً داخل كل فئة في استعلام واحد فائق الكفاءة.

🤔 سؤال تحدي كبار المهندسين:

ما هو الفرق بين RANK() و DENSE_RANK() عندما يتساوى موظفان في نفس الراتب بالمركز الثاني؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

إذا تساوى موظفان في المركز الثاني (المرتبة 2)، فإن دالة RANK() ستعطي الموظف التالي المرتبة 4 (تترك فجوة في الترقيم 1, 2, 2, 4). أما دالة DENSE_RANK() فلا تترك أي فجوات وتعطي الموظف التالي المرتبة 3 مباشرة (1, 2, 2, 3).

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

WITH RankedProducts AS (                             // 1. CTE لتصنيف المنتجات
  SELECT id, name, category, sales_count,            // حقول المنتج
    ROW_NUMBER() OVER (                              // ترقيم ترتيبي داخل كل فئة
      PARTITION BY category                          // تقسيم النوافذ حسب الفئة
      ORDER BY sales_count DESC                      // فرز بالأعلى مبيعاً
    ) as rank                                        // اسم عمود الترتيب
  FROM products                                      // جدول المنتجات
)                                                    // نهاية الـ CTE
SELECT * FROM RankedProducts WHERE rank <= 3; // 2. جلب أفضل 3 في كل قسم // استخراج Top-3 لكل فئة

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
// خطأ شائع: محاولة وضع Window Function داخل جملة WHERE مباشرة
SELECT name, salary FROM employees WHERE ROW_NUMBER() OVER (ORDER BY salary) <= 5;
// خطأ Syntax Error: Window functions غير مسموحة في WHERE لأنها تنفذ بعد تصفية الصفوف!
✅ الحل الهندسي القياسي (Best Practice)
// الحل الهندسي: تغليف الاستعلام داخل CTE أو Subquery
WITH Ranked AS (
  SELECT name, salary, ROW_NUMBER() OVER (ORDER BY salary DESC) as rn FROM employees
)
SELECT * FROM Ranked WHERE rn <= 5;

التشخيص الهندسي: محرك SQL ينفذ جملة WHERE قبل حساب الـ Window Functions، ولذلك يجب استخدام CTE لتصفية النتائج بناءً على قيم النوافذ.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

سؤال إنترفيو للمهندسين الكبار: كيف تحل مشكلة "Gaps and Islands" الشهيرة في SQL لحساب أطول سلسلة أيام متتالية قام فيها المستخدم بتسجيل الدخول؟

نحلها باستخدام دمج ROW_NUMBER مع التواريخ: 1. نقوم بحساب log_date - (ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY log_date) * INTERVAL '1 day') as grp_date. 2. إذا كانت الأيام متتالية، فإن فارق الطرح سينتج نفس التاريخ الثابت تماماً لجميع الأيام المتتالية (Island). 3. نقوم بعد ذلك بعمل GROUP BY user_id, grp_date مع حساب COUNT(*) لحساب أطول سلسلة أيام متصلة في استعلام قياسي فائق السرعة.
