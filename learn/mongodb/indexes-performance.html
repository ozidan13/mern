المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

الاستعلام في مجموعة MongoDB تحتوي على 500,000 مستند بدون وجود فهارس (Indexes) يجبر المحرك على عمل مسح كامل للمجموعة (COLLSCAN: Collection Scan)، مما يعني قراءة كل بايت على القرص واستهلاك 100% من المعالج وبطء الاستجابة لعدة ثوانٍ! بإنشاء فهرس B-Tree صحيح، يتحول الاستعلام إلى فحص فهارس فوري (IXSCAN) يستغرق أقل من 2 ميلي ثانية!

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
الفحص الموضعي بـ IXSCAN

المحرك يبحث في شجرة الفهرس المرتبة ويصل للمستندات المطلوبة بـ O(log N).

2
قاعدة ESR للفهارس المركبة

Equality (المساواة أولاً) ← Sort (حقول الفرز ثانياً) ← Range (حقول النطاق مثل $gte أخيراً).

3
فهارس الحذف التلقائي (TTL Indexes)

حذف جلسات المستخدمين ورموز التحقق تلقائياً من الذاكرة بعد مرور وقت محدد (expireAfterSeconds).

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

ما هي ميزة الاستعلام المغطى بالكامل (Covered Query) في MongoDB؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

هو استعلام يستطيع MongoDB إرجاع جميع الحقول المطلوبة فيه من شجرة الفهرس (Index) مباشرة دون الحاجة للمس أو قراءة مستندات الـ Collection في الذاكرة نهائياً (totalDocsExamined: 0)، وهو أسرع أنواع الاستعلامات في المحرك.

تشريح الكود سطراً بسطر · Code Anatomy

1: // Compound Index following ESR Rule (Equality -> Sort -> Range) // تطبيق قاعدة ESR
2: db.orders.createIndex({ status: 1, createdAt: -1, total: 1 }); // إنشاء الفهرس المركب
3: // TTL Index to auto-expire sessions after 24 hours // فهرس الحذف الزمني التلقائي
4: db.sessions.createIndex({ createdAt: 1 }, { expireAfterSeconds: 86400 }); // حذف آلي
