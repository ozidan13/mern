BSON Document Model vs Tables

نموذج المستندات BSON مقابل الجداول العلائقية: تصميم المخططات، والتضمين (Embedding) مقابل الإسناد (Referencing)

Teaches: MongoDB 8.x Architecture Level 1 25 mins · دقيقة
Learning Objectives · أهداف الدرس
  • Understand the BSON (Binary JSON) storage engine and ObjectId generation anatomy.
  • Compare Document collections with Relational tables (Row vs Document, Table vs Collection).
  • Master the golden schema rule: Data that is accessed together should be stored together (Embedding).
  • Determine when to Reference (1:Many high cardinality) vs when to Embed (1:Few).

1. Core Concept & Mechanics · الفكرة الأساسية

Real-Life Analogy · تشبيه مجلد الملفات الشامل مقابل الأوراق المتناثرة

في قواعد البيانات العلائقية التقليدية (SQL)، لكي تقرأ بيانات مستخدم وعناوينه وطلباته، عليك تجميع أوراق متناثرة من 4 جداول مختلفة عبر عمليات دمج معقدة (JOINs). أما في MongoDB، فالأمر يشبه مجلداً بلاستيكياً واحداً (Document) تضع فيه بطاقة المستخدم وعناوينه مدمجة بداخله كـ Sub-document: تفتح المجلد مرة واحدة فتجد كل شيء جاهزاً في قراءة قرصية واحدة (Single Disk Read)!

Definition & Purpose

MongoDB is a document-oriented NoSQL database. It stores records as BSON documents (Binary JSON), grouping them into flexible collections without rigid table schemas. It enables dynamic schemas, nested arrays, and high-throughput read/write operations.

تعتمد قاعدة بيانات MongoDB على تخزين البيانات بصيغة BSON (Binary JSON). تتيح للمطورين تمثيل كائنات معقدة ومتداخلة ومصفوفات داخل نفس المستند بدون الحاجة لجداول وسيطة أو قيود صارمة للمخطط.

Key Architectural Equivalents · المقابل بين SQL و MongoDB

1
Table → Collection (المجموعة)

المجموعة تضم مستندات من نفس الفئة (مثل users أو posts) بدون فرض نفس الحقول على كل المستندات.

2
Row → Document / BSON (المستند)

المستند يمثل سجلاً واحداً يحمل معرفاً فريداً _id (ObjectId) بحد أقصى للحجم 16MB.

3
Column → Field (الحقل)

الحقل يقبل جميع الأنواع القياسية بالإضافة للمصفوفات (Arrays) والمستندات الفرعية المضمنة (Embedded Documents).

5. Deep Dive & Complexity Analysis · التحليل والتعقيد

Read Performance (Embedded)
1 Disk Seek (Zero JOINs)

تضمين البيانات المرتبطة يسمح بقراءة السجل وأبنائه في عملية قراءة قرصية ذرية واحدة.

BSON Size Limit
16 MB Max Document

الحد الأقصى المطلق لحجم أي مستند BSON واحد في MongoDB هو 16 ميجابايت لمنع استهلاك مفرط للذاكرة.

Anatomy of a MongoDB ObjectId (12 Bytes)
  • 4 Bytes: Unix Timestamp بالثواني (يمكن استخراج تاريخ الإنشاء من المعرف مباشرة).
  • 5 Bytes: معرف فريد للعملية والآلة العشوائية (Process & Machine Identifier).
  • 3 Bytes: عداد تراكمي متزايد (Incrementing Counter).

6. Practice & Common Mistakes · أخطاء شائعة

Unbounded Array Growth (تضخم المصفوفة اللانهائي)
// ❌ DANGEROUS (Unbounded array hits 16MB limit)
{ _id: 1, logs: [ ...millionsOfLogEntries ] }
// ✅ SAFE (Referenced collection per log entry)
{ _id: 101, serverId: 1, message: "OK", timestamp: ... }

التشخيص: تخزين سجلات أو أحداث تنمو بلا سقف داخل مصفوفة في نفس المستند سيؤدي حتماً لاختراق حاجز الـ 16MB وانهيار عمليات الكتابة.

8. Production Notes & Interviews · في بيئة العمل والمقابلات

Interview Question: When to choose MongoDB over PostgreSQL?

Q: Under what architectural requirements should a team select MongoDB over a relational database?

الإجابة: عندما تكون هياكل البيانات هرمية ومتغيرة المخطط (Polymorphic schema)، وحجم الكتابة مرتفعاً جداً ويتطلب توزيعاً أفقياً مرناً (Sharding)، وحيث تقرأ البيانات دائماً ككتلة واحدة مدمجة (مثل كتالوجات المنتجات والتغذية الإخبارية).
