MongoDB Aggregation Framework: $match, $group, $lookup, $unwind & $facet

خط أنابيب التجميع (Aggregation Pipeline): المعالجة التحليلية والربط في MongoDB

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم تدفق مراحل الـ Pipeline وترتيبها الأمثل للاستفادة من الفهارس.
  • تجميع وحساب الإحصائيات باستخدام $group ومشغلات التجميع ($sum, $avg, $push).
  • تنفيذ عمليات الربط بين المجموعات (Left Outer Joins) باستخدام $lookup.

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

عندما تحتاج لحساب تقارير مالية معقدة، تجميع المبيعات شهرياً، أو ربط مستندات من مجموعتين مختلفتين، استعلامات find البسيطة تقف عاجزة. إطار التجميع Aggregation Pipeline هو أقوى محرك تحليلي في NoSQL؛ يعمل كخط إنتاج مصنعي متسلسل يمرر المستندات عبر مراحل متتابعة ($match ← $group ← $lookup ← $project) بسرعة فائقة على مستوى المحرك.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
التصفية المبكرة بـ $match

وضع $match في أول مرحلة لتصفية المستندات بالاعتماد على الفهارس وتقليل حجم البيانات الممررة للمراحل التالية.

2
التجميع وحساب المقاييس بـ $group

تقسيم البيانات إلى مجموعات بناءً على مفتاح _id وحساب المجاميع والنسب.

3
الربط الخارجي بـ $lookup

جلب بيانات المجموعات الأخرى عبر مطابقة localField مع foreignField.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

لماذا يحظر وضع مرحلة $lookup قبل مرحلة $match في خط أنابيب التجميع؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لأن وضع $lookup أولاً سيجبر المحرك على عمل Join لكل مستندات المجموعة في الذاكرة قبل التصفية، بينما وضع $match أولاً يقلص عدد المستندات بنسبة 90% قبل عمل الربط مما يوفر الذاكرة ويسرع الاستعلام 10x.

تشريح الكود سطراً بسطر · Code Anatomy

1: const stats = await db.collection("orders").aggregate([ // بدء خط الأنابيب
2:   { $match: { status: "completed" } },          // المرحلة 1: تصفية تعتمد على الفهارس
3:   { $group: { _id: "$userId", totalSpent: { $sum: "$total" }, count: { $sum: 1 } } }, // المرحلة 2: تجميع وحساب
4:   { $sort: { totalSpent: -1 } }                 // المرحلة 3: فرز تنازلي
5: ]).toArray();                                   // تنفيذ وإرجاع مصفوفة

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
aggregate([{ $group: ... }, { $match: ... }]) /* يفقد استخدام الفهارس ويبطئ الاستعلام */
✅ الحل الهندسي الصحيح (Best Practice)
aggregate([{ $match: ... }, { $group: ... }]) /* تصفية أولاً تستغل الـ Index بالكامل */

التشخيص الهندسي: مرحلة $group تلغي إمكانية استخدام الفهارس للمراحل التالية، لذا يجب وضع $match في البداية دائماً.

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): ما هي مرحلة $facet في خط أنابيب التجميع وفيمَ تُستخدم؟

مرحلة `$facet` تتيح تنفيذ عدة خطوط أنابيب فرعية متوازية داخل نفس الاستعلام على نفس مجموعة البيانات؛ وتُستخدم بشكل شائع جداً في تطبيقات المتاجر لتوليد (نتائج المنتجات المقسمة لصفحات + مصفوفة فلاتر الفئات والمصنعين + توزيع الأسعار) في طلب واحد فائق السرعة.
