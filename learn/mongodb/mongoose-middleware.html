Mongoose Middleware: Document, Query, Aggregate Hooks & Virtual Population

برمجيات Mongoose الوسيطة (Hooks): خطافات المستندات والاستعلامات والتعبئة الافتراضية (Virtuals)

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم الفرق الجوهري بين خطافات المستندات (Document Middleware: this = doc) وخطافات الاستعلام (Query Middleware: this = query).
  • تطبيق خطافات pre("save") لتشفير كلمات المرور تلقائياً فقط عند تعديل الحقل isModified("password").
  • بناء نمط الحذف الناعم (Soft Delete) باستخدام خطافات pre(/^find/) لتصفية السجلات المحذوفة تلقائياً.
  • استخدام الحقول الافتراضية (Virtual Population) لربط المجموعات بمرونة دون تخزين مصفوفات معرفات ضخمة.

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

مكتبة **Mongoose** هي الـ ODM (Object Document Mapper) الأكثر شعبية في عالم Node.js. واحدة من أقوى ميزات Mongoose هي **البرمجيات الوسيطة (Middleware Hooks)** التي تتيح لك اعتراض دورة حياة البيانات قبل أو بعد حفظها، تعديلها، أو حذفها. لكن المطورين يقعون في فخاخ شهيرة تدمر البيانات: - مطور يكتب schema.pre('save') لتشفير كلمة المرور بـ Bcrypt، وعندما يقوم المستخدم بتعديل اسمه فقط، يُعاد تشفير كلمة المرور المشفرة بالفعل فتتلف ويصبح المستخدم عاجزاً عن تسجيل الدخول للأبد! - مطور آخر يستخدم User.findByIdAndUpdate() ويفاجأ بأن خطاف pre('save') لم يعمل نهائياً ولم يتم تشفير كلمة المرور! السبب هو عدم فهم الفرق الجوهري بين **Document Middleware** (التي تعمل على مستندات تم تحميلها بـ .save()) و **Query Middleware** (التي تعمل مباشرة على استعلامات قاعدة البيانات مثل findOneAndUpdate). في هذا الدرس، هنفكك دورة حياة Mongoose بالكامل، وهنتعلم إزاي نبني نظام **Soft Delete** و **Virtual Population**.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

01

خطافات المستندات (Document Middleware)

تعمل عند استدعاء doc.save() أو doc.validate()؛ ويكون متغير this يشير إلى كائن المستند الفعلي في الذاكرة.

02

فحص التعديلات بـ doc.isModified("field")

التحقق مما إذا كان حقل معين (مثل password) قد تم تغييره فعلياً قبل تشغيل العمليات المكلفة مثل التشفير.

03

خطافات الاستعلامات (Query Middleware)

تعمل عند استدعاء find() أو updateOne()؛ ويكون متغير this يشير إلى كائن الاستعلام Query وليس المستند.

04

تطبيق الحذف الناعم (Soft Delete Pattern)

اعتراض جميع استعلامات البحث بـ pre(/^find/) وإضافة شرط { isDeleted: { $ne: true } } تلقائياً دون كتابته في كل مسار.

05

التعبئة الافتراضية بـ Virtual Population

إنشاء علاقات وهمية schema.virtual("posts") تتيح استخدام populate("posts") دون تخزين مصفوفة معرفات في قاعدة البيانات.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي كبار المهندسين:

لماذا لا يتم تشغيل خطاف schema.pre("save") عند استدعاء User.updateOne({ _id }, { name }) أو User.findByIdAndUpdate()؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لأن updateOne و findByIdAndUpdate هي عمليات استعلام مباشرة تُرسل من Mongoose إلى محرك MongoDB دون تحميل المستند إلى ذاكرة جافاسكريبت أو إنشاء Document Instance. وبالتالي يتم تشغيل خطافات الاستعلامات Query Hooks مثل schema.pre("findOneAndUpdate") وليس خطافات المستندات pre("save"). لتشغيل pre("save")، يجب جلب المستند بـ findById ثم تعديله واستدعاء doc.save().

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

userSchema.pre("save", async function (next) {       // خطاف المستند قبل الحفظ
  if (!this.isModified("password")) return next(); // حماية عدم التكرار // فحص التعديل الفعلي
  const salt = await bcrypt.genSalt(12);             // توليد Salt قوي
  this.password = await bcrypt.hash(this.password, salt); // تشفير كلمة المرور
  next();                                            // تمرير العملية
});                                                  // نهاية خطاف الحفظ
userSchema.pre(/^find/, function () {                // خطاف استعلامات البحث (Regex)
  this.where({ isDeleted: { $ne: true } }); // تصفية الحذف الناعم تلقائياً // حجب السجلات المحذوفة
});                                                  // نهاية خطاف البحث

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
// خطأ كارثي: تشفير الباسورد في pre('save') بدون فحص isModified
userSchema.pre("save", async function() {
  this.password = await bcrypt.hash(this.password, 10); // يعيد تشفير الـ Hash المشفر عند كل تعديل للملف الشخصي!
});
✅ الحل الهندسي القياسي (Best Practice)
// الحل الصحيح: فحص isModified دائماً
userSchema.pre("save", async function() {
  if (!this.isModified("password")) return;
  this.password = await bcrypt.hash(this.password, 12);
});

التشخيص الهندسي: عدم فحص isModified يؤدي لإعادة تشفير الهاش المشفر مسبقاً وتلف كلمات المرور للمستخدمين.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

سؤال إنترفيو للمهندسين الكبار: ما هو الفرق بين lean() و استعلام Mongoose العادي ومتى يجب استخدامه لزيادة سرعة الخادم بنسبة 400%؟

استعلام Mongoose العادي يقوم بتحويل كل وثيقة مسترجعة إلى Mongoose Document كامل محمّل بالـ Getters والـ Setters والـ Internal State والـ Change Tracking وخطافات الـ Middleware، مما يستهلك ذاكرة RAM ووقت معالجة كبير في الـ V8. عند استخدام .lean()، يتجاوز Mongoose كل هذا البناء ويُرجع كائنات جافاسكريبت خام نقيّة (Plain JavaScript Objects - POJO)، مما يقلل استهلاك الـ RAM بنسبة تصل إلى 70% ويسرع استعلامات القراءة (GET APIs) بنسبة تفوق 400%.
