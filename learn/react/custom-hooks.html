Custom Hooks Architecture: Headless UI, State Encapsulation & Composition

هندسة الـ Custom Hooks: فصل المنطق عن العرض (Headless UI) والكبسلة المتقدمة

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • استخراج وإعادة استخدام المنطق البرمجي المعقد عبر Custom Hooks نظيفة تبدأ بـ use.
  • تطبيق نمط Headless UI لفصل منطق الحسابات وحالات الـ State تماماً عن أكواد الـ JSX والتنسيقات.
  • بناء Hooks إنتاجية شائعة (useDebounce, useLocalStorage, useMediaQuery, useEventListener).
  • إدارة وتنظيم دورات الحياة المعقدة وتفادي تسريبات الذاكرة داخل الـ Hooks المخصصة.

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

في المشاريع المتوسطة والكبيرة، تجد نفس الكود يتكرر في 10 مكونات مختلفة: كود جلب البيانات من الـ API مع حالات (Loading, Error, Data)، كود حفظ الإعدادات في localStorage، أو كود الاستماع لحجم الشاشة لتحديد إذا كان الموبايل في الوضع الرأسي. نسخ ولصق هذا المنطق داخل كل مكون يجعل الصيانة كابوساً: لو اكتشفت ثغرة في طريقة الحفظ في localStorage، ستضطر لتعديل 10 ملفات مختلفة! **الـ Custom Hooks** هي أقوى آلية لإعادة استخدام المنطق في ريآكت. الـ Custom Hook هي دالة جافاسكريبت عادية تبدأ بكلمة use وتستطيع استدعاء خطافات ريآكت الأخرى (useState, useEffect, useMemo) بداخلها. الأهم من ذلك هو أن الـ Custom Hook يتيح لك تطبيق معمارية **Headless UI**: بناء المنطق البرمجي المعقد وحالاته واختباره بالكامل بمعزل تام عن طريقة عرضه في الواجهة. في هذا الدرس، هنبني مجموعة من أشهر الـ Production Custom Hooks من الصفر، وهنتعلم القواعد المعمارية لتأليف ودمج الـ Hooks معاً.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

01

ميثاق التسمية وقواعد الـ Hooks الصارمة

يجب أن تبدأ الدالة بـ use (مثل useDebounce) لتفعيل فحص linter لقواعد الـ Hooks ولضمان استدعائها في المستوى الأعلى فقط.

02

كبسلة الحالة والآثار الجانبية (Encapsulating State & Effects)

عزل منطق useState و useEffect داخل الـ Hook وإرجاع واجهة برمجية بسيطة (Tuple أو Object) للمكون المستدعي.

03

عزل مساحات الحالة (Unique State per Component Instance)

كل مكون يستدعي الـ Custom Hook يحصل على نسخته المستقلة تماماً من الحالة، فالـ Hooks تشارك المنطق وليس البيانات.

04

نمط دمج الخطافات (Hook Composition)

بناء Hooks متقدمة بالاعتماد على Hooks أبسط (مثلاً بناء useAuth بالاعتماد على useLocalStorage و useFetch).

05

تنظيف الموارد وإلغاء الاشتراكات (Cleanup Contracts)

ضمان تنظيف كل مستمعي الأحداث والـ Timers المفتوحة داخل الـ Hook عند إلغاء تركيب المكون المستهلك.

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

قطعاً لا! الـ Custom Hooks تشارك فقط "المنطق البرمجي والهيكل" (Stateful Logic)، ولكن كل مكون يستدعي الـ Hook يحصل على مساحة حالة معزولة ومستقلة تماماً في شجرة الـ Fiber الخاصة به. لمشاركة نفس البيانات المشتركة بين المكونات، يجب استخدام React Context أو مكتبة إدارة حالة عالمية مثل Zustand.

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

export function useLocalStorage(key, initialValue) { // تعريف Custom Hook يقبل المفتاح والقيمة
  const [storedValue, setStoredValue] = useState(() => { // تهيئة الحالة بكسل عبر دالة
    try {                                            // حماية من أخطاء الـ Parsing
      const item = window.localStorage.getItem(key); // قراءة القيمة المخزنة
      return item ? JSON.parse(item) : initialValue; // إرجاع القيمة أو القيمة الافتراضية
    } catch { return initialValue; }                 // التعامل مع تعطيل التخزين
  });                                                // نهاية useState
  const setValue = (value) => {                   // دالة التحديث الآمنة
    setStoredValue(value);                           // تحديث حالة ريآكت
    window.localStorage.setItem(key, JSON.stringify(value)); // المزامنة مع متصفح العميل
  };                                                 // نهاية دالة التحديث
  return [storedValue, setValue];                    // إرجاع Tuple مطابق لـ useState
}                                                    // نهاية الـ Custom Hook

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
// خطأ شائع: تسمية الدالة بدون بادئة use
function calculateWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth); // تحذير linter: Hooks can only be called inside custom hooks or components
  return width;
}
✅ الحل الهندسي القياسي (Best Practice)
// الحل الصحيح: الالتزام الصارم بتسمية use
function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth); // سليم وتتعرف عليه أدوات الفحص
  useEffect(() => { ... }, []);
  return width;
}

التشخيص الهندسي: بادئة use هي العلامة التي تستخدمها أدوات React Linter وقواعد الـ Compiler للتحقق من أنك لا تستدعي الخطافات داخل شروط if أو حلقات تكرارية.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

سؤال إنترفيو للمهندسين الكبار: كيف تبني Hook مخصص useEvent (أو useEffectEvent في React 19) لقراءة أحدث قيم الـ Props والـ State داخل التأثيرات دون وضعها في مصفوفة الاعتماديات ودون التسبب في إعادة تشغيل الـ Effect؟

نستخدم نمط useEvent (أو خطاف useEffectEvent الرسمي في ريآكت 19): نحفظ الدالة الممررة داخل useRef في كل Render ref.current = handler، ثم نغلفها بدالة ثابتة بـ useCallback(() => ref.current(...), []). هذا يتيح للدالة قراءة أحدث قيم الـ State والـ Props دائماً بدون أن يتغير مرجعها، مما يسمح باستدعائها داخل useEffect دون الحاجة لإضافتها لمصفوفة الاعتماديات، مانعاً إعادة تشغيل الـ Effect بشكل غير مرغوب.
