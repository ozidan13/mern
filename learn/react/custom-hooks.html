الهوكس المخصصة (Custom Hooks): استخراج المنطق المعقد وتركيب السلوكيات

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم قواعد الهوكس (Rules of Hooks) وكيف يتعرف محرك ريآكت على بادئة use.
  • بناء Custom Hooks شائعة مثل useLocalStorage و useDebounce و useWindowSize.
  • تركيب عدة هوكس معاً (Hook Composition) لبناء حلول متكاملة.

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

تكرار منطق جلب البيانات وإدارة الاتصال بالشبكة أو الـ LocalStorage عبر مكونات متعددة يجعل الكود مكرراً وممتلئاً بـ useEffects متشابهة. الـ Custom Hooks هي الطريقة القياسية لاستخراج منطق الحالة (Stateful Logic) وتغليفه في دوال نقية قابلة لإعادة الاستخدام والاختبار بمعزل تام عن الواجهة.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
بادئة use الإلزامية

تسمية الدالة بـ use تتيح لـ Linter التأكد من الالتزام بقواعد الهوكس.

2
مشاركة المنطق وليس الحالة

كل استدعاء للـ Custom Hook يحصل على حالة خاصة معزولة تماماً.

3
واجهة برمجية نظيفة (API Contract)

إرجاع مصفوفة [value, setter] أو كائن { data, loading, error } حسب طبيعة الاستخدام.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

هل تتشارك المكونات التي تستدعي نفس الـ Custom Hook نفس الحالة في الذاكرة؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لا، كل مكون يستدعي Custom Hook ينشئ نسخة حالة مستقلة ومعزولة تماماً في شجرة الـ Fiber الخاصة به؛ الـ Custom Hook يشارك المنطق فقط وليس الحالة.

تشريح الكود سطراً بسطر · Code Anatomy

1: export function useDebounce(value, delay = 300) { // هوك تأخير القيمة
2:   const [debounced, setDebounced] = useState(value); // حالة القيمة المؤجلة
3:   useEffect(() => {                          // تأجيل التحديث
4:     const timer = setTimeout(() => setDebounced(value), delay); // بدء المؤقت
5:     return () => clearTimeout(timer);        // تنظيف المؤقت
6:   }, [value, delay]);                           // التبعية
7:   return debounced;                             // إرجاع القيمة المستقرة
8: }                                               // نهاية الهوك

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
function fetchUser() { useState(); } /* خطأ: عدم البدء ببادئة use يكسر قواعد الـ Linter */
✅ الحل الهندسي الصحيح (Best Practice)
function useUser() { useState(); } /* صحيح وملتزم بالمعيار */

التشخيص الهندسي: البادئة use ضرورية لتمكين أدوات الفحص من التحقق من صحة استدعاء الهوكس وعدم وضعها داخل شروط.
