رؤية الواقع العملي · Real-World Context & Mental Model

في تطبيقات SPA التقليدية، التنقل بين الصفحات كان يسبب تحميل الشاشات ثم ظهور دوائر تحميل مزعجة (Spinners) بسبب جلب البيانات بعد رسم الصفحة (Fetch-on-Render). معمارية React Router v7 الحديثة تقدم نمط الـ Data Routers والمسارات المتداخلة (Nested Routes) مع دوال الـ Loaders التي تجلب بيانات الصفحة بالتوازي قبل رسمها!

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
<a href="dashboard.html">Dashboard</a> /* يسبب Full Page Refresh ويفقد حالة الـ SPA بالكامل */

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): ما هو الفرق بين Fetch-on-Render و Render-as-You-Fetch في معمارية التوجيه؟

في Fetch-on-Render ينتظر المكون حتى يُرسم في الـ DOM ثم يبدأ جلب بياناته عبر useEffect مسبباً شلالات تحميل بطيئة. أما في Render-as-You-Fetch (مثل Loaders في Router v7) تبدأ عملية جلب البيانات ومطابقة المسار وتنزيل الكود في نفس اللحظة بالتوازي قبل الرسم.
