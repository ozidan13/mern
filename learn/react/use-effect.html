المفهوم الخاطئ الأشهر عن useEffect

أكبر غلطة بيقع فيها المطور هو التعامل مع useEffect كأنها مجرد مكان لرمي أي كود بعد الـ Render! فريق ريآكت أكد: إذا كنت بتستخدم الـ Effect عشان تحدث State تانية معتمدة على State أولى، فده تصميم خاطئ ويبطئ التطبيق. الـ Effect اتعملت فقط للمزامنة مع عالم خارجي: زي الاشتراك في WebSocket، أو التعامل مع الـ DOM الأصلي (HTML5 Canvas)، أو تشغيل Timer، أو جلب بيانات عبر الشبكة مع إلغاء الطلبات السابقة.

7. أخطاء شائعة وفخاخ يقع فيها الجميع · Common Pitfalls

نسيان دالة التنظيف مع التايمرز (Dangling Interval)
// ❌ كارثة: التايمر يفضل شغال للأبد ويسرب الذاكرة
useEffect(() => {
  setInterval(() => tick(), 1000);
}, []);
// ✅ مسح التايمر في دالة الـ Cleanup
useEffect(() => {
  const id = setInterval(() => tick(), 1000);
  return () => clearInterval(id);
}, []);

التشخيص الهندسي: إذا لم تقم بمسح الـ Interval، سيظل يعمل في خلفية المتصفح ويستدعي دالة التحديث على مكون ميت.

قاموس المصطلحات الأساسية · Mini-Glossary

Cleanup Function
الدالة التي تعيدها من داخل useEffect وتنفذها ريآكت لتنظيف الموارد قبل إعادة التشغيل أو عند إزالة المكون.
Race Condition
خلل يحدث عندما تصل نتيجة طلب شبكة قديم بعد نتيجة طلب شبكة أحدث فيعرض التطبيق بيانات خاطئة.

الإجابة الهندسية:
1. تحويل وحساب البيانات: احسبها مباشرة في جسم الدالة (const filtered = items.filter(...)).
2. معالجة أحداث المستخدم: ضع المنطق في معالج الحدث مباشرة (onClick أو onSubmit) بدلاً من وضع State ثم مراقبتها بـ Effect.
3. جلب البيانات الإنتاجي: استخدم مكتبات متخصصة مثل TanStack Query (React Query) للتعامل مع الـ Caching والـ Deduplication وإعادة المحاولة التلقائية.
