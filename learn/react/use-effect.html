Effects with useEffect & Lifecycle Synchronization

الآثار الجانبية (Side Effects) مع useEffect: المزامنة، مصفوفة الاعتماديات، ودالة التنظيف Cleanup

Learning Objectives · أهداف الدرس

  • Master the Dependency Array: no deps vs [] vs [dep1, dep2].
  • Prevent memory leaks and race conditions using the Cleanup function.

1. Core Concept & Mechanics · الفكرة الأساسية

Real-Life Analogy · تشبيه جهاز التكييف الذكي والمستشعر

تخيّل جهاز تكييف ذكي في غرفتك مزوداً بمستشعر حرارة (الـ Dependency). أنت لا تخبر التكييف كل ثانية بأن يغير سرعته، بل تضبط المستشعر: كلما تغيرت درجة حرارة الغرفة إلى قيمة جديدة، يبدأ التكييف في مزامنة نفسه تلقائياً (Synchronize) مع الحالة الخارجية. وعندما تغلق الغرفة وتغادر، يقوم التكييف بإطفاء نفسه وفصل الكهرباء (Cleanup Function) لتوفير الطاقة ومنع الحوادث!

Definition & Purpose

In React, useEffect allows you to synchronize a component with an external system (such as browser APIs, timers, websockets, or network requests). It runs after rendering and painting have completed.

الـ useEffect هو أداة لمزامنة المكون مع أنظمة خارجية لا تخضع لتحكم ريآكت المباشر (مثل الـ DOM APIs المباشرة، اشتراكات الـ WebSockets، والمؤقتات). ينفذ الـ Effect دائماً بعد اكتمال الرسم على الشاشة لضمان عدم حظر تجربة المستخدم.

The Three Dependency Modes · الأوضاع الثلاثة لمصفوفة الاعتماديات

1
1. No Dependency Array: useEffect(fn)

ينفذ التأثير بعد كل عملية إعادة رسم (Every Render) بدون استثناء. نادراً ما يُستخدم ويجب الحذر منه لتجنب الحلقات اللانهائية.

2
2. Empty Array: useEffect(fn, [])

ينفذ التأثير مرة واحدة فقط عند ظهور المكون لأول مرة على الشاشة (Mount).

3
3. With Dependencies: useEffect(fn, [roomId])

ينفذ التأثير عند أول ظهور، ثم يُعاد تنفيذه فقط إذا تغيرت قيمة أي متغير موجود داخل المصفوفة (عبر Object.is).

What happens if you update a state variable inside a useEffect that has no dependency array?

ماذا يحدث عند تحديث State داخل useEffect بدون تمرير مصفوفة اعتماديات؟

ستحدث حلقة إعادة رسم لا نهائية (Infinite Loop)! لأن تحديث الـ State يعيد رسم المكون، مما يشغل الـ Effect من جديد، فيحدث الـ State مجدداً بلا توقف.

5. Deep Dive & Complexity Analysis · التحليل والتعقيد

Dependency Diffing Cost
O(D) Dependencies

يقوم React بمقارنة كل عنصر في مصفوفة الاعتماديات بقيمته السابقة عبر Object.is.

Unmount Cleanup
O(1) Garbage Collect

تضمن دالة الـ Cleanup إلغاء المؤقتات والاشتراكات، مما يسمح لجامع القمامة بتحرير الذاكرة فوراً.

You Might Not Need an Effect: Modern React 19 Guidelines
  • حساب البيانات من Props: لا تستخدم Effect، احسبها لحظياً في جسم الدالة (Render time).
  • الاستجابة لضغطة زر: ضع الكود في معالج الحدث (Event Handler)، وليس في Effect.
  • معالجة النماذج: استخدم React 19 Form Actions بدلاً من مزامنة الـ Effects.

6. Practice & Common Mistakes · أخطاء شائعة

Race Condition in Async Data Fetching
// ❌ BUGGY (Fast tab switch shows wrong data)
useEffect(() => {
  fetchUser(id).then(u => setUser(u));
}, [id]);
// ✅ FIXED (Ignored stale responses)
useEffect(() => {
  let ignore = false;
  fetchUser(id).then(u => { if (!ignore) setUser(u); });
  return () => { ignore = true; };
}, [id]);

التشخيص: إذا تنقل المستخدم بسرعة بين المستخدمين، قد تصل استجابة الطلب القديم متأخرة وتستبدل بيانات المستخدم الحديث!

Mini-Glossary · قاموس المصطلحات

Side Effect
أي عملية تؤثر على العالم الخارجي خارج نطاق الدالة النقية، مثل تعديل الـ DOM أو جلب بيانات الشبكة.
Cleanup Function
دالة اختيارية تعيدها دالة الـ Effect لتنظيف الموارد والاشتراكات القديمة قبل تشغيل التأثير الجديد.

Interview Question: React StrictMode Double Invocation

Q: Why does useEffect run twice on mount in development under React StrictMode?

الإجابة: يتعمد React في بيئة التطوير تشغيل Setup → Cleanup → Setup للتأكد من أن المطور قد كتب دالة تنظيف صحيحة وأن التأثير مرن وقابل لإعادة التركيب دون التسبب في تسريبات ذاكرة.
