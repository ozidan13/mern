Synthetic Events & Delegation in React 19: Pooling Removal & Native Interop

نظام الأحداث المركبة (Synthetic Events) وتفويض الأحداث في ريآكت 19

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم بنية الأحداث المركبة SyntheticEvent وكيف توحد ريآكت سلوك المتصفحات المختلفة.
  • تشريح آلية تفويض الأحداث (Event Delegation) وربط المستمعين بجذر التطبيق (React Root Container).
  • فهم إلغاء ميزة Event Pooling في الإصدارات الحديثة والتعامل الآمن مع الأحداث اللاتزامنية.
  • إدارة منع السلوك الافتراضي (e.preventDefault) ووقف الانتشار (e.stopPropagation).

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

في جافاسكريبت العادية، لو عندك قائمة فيها 1000 عنصر، وإضافة event listener لكل عنصر button.addEventListener('click') هتحجز 1000 مكان في الذاكرة وهتبطئ المتصفح جداً. ريآكت حلت المشكلة دي بعبقرية من خلال معمارية "تفويض الأحداث" (Event Delegation) ونظام "الأحداث المركبة" (Synthetic Events). عندما تكتب onClick={handleClick} على أي زرار في ريآكت، ريآكت مش بتضيف المستمع على الزرار نفسه في الـ DOM! ريآكت بتضيف مستمع وحيد فقط على جذر التطبيق (Root Container: #root)، وتلتقط كل الأحداث الصاعدة (Event Bubbling) وتغلفها في كائن موحد اسمه SyntheticEvent عشان يشتغل بنفس السلوك في كروم وسفاري وفايرفوكس بدون أي فروق. في هذا الدرس، هنتعلم إزاي بيشتغل نظام الأحداث في ريآكت 19، إزاي تدمج ريآكت مع مكتبات خارجية بتستخدم Native DOM Events، ولماذا تم إلغاء Event Pooling لتسهيل استخدام async/await في معالجات الأحداث.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

01

آلية التفويض المركزي (Centralized Delegation)

يتم تسجيل مستمع واحد فقط لكل نوع حدث على حاوية createRoot(#root) بدلاً من عناصر الـ DOM الفردية.

02

التغليف في SyntheticEvent

عند وقوع الحدث، تنشئ ريآكت كائناً مركباً يوفر نفس واجهة W3C القياسية (target, currentTarget, preventDefault) عبر كل المتصفحات.

03

إلغاء Event Pooling نهائياً

في ريآكت 17+ و 19، لم يعد كائن الحدث يُعاد تدويره، مما يسمح بقراءة e.target بأمان داخل الدوال اللاتزامنية والـ setTimeout.

04

مراحل الحدث: Capture و Bubble في JSX

استخدم onClick للمرحلة الصاعدة العادية (Bubble Phase) أو onClickCapture للاعتراض في المرحلة الهابطة (Capture Phase).

05

التوافق مع أحداث الـ DOM الأصلية (Native Interop)

استخدام e.nativeEvent للوصول للحدث الأصلي للمتصفح عند التعامل مع مكتبات الخرائط أو محررات النصوص المتقدمة.

ما الفرق بين e.target و e.currentTarget داخل معالج حدث ريآكت؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

الخاصية e.target تشير إلى العنصر الدقيق الفعلي الذي ضغط عليه المستخدم (مثلاً أيقونة داخل الزر). أما e.currentTarget فتشير دائماً إلى العنصر الذي تم ربط معالج الحدث به في JSX (وهو الزر نفسه).

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

function SearchForm({ onSearch }) {                  // مكون نموذج البحث
  const handleSubmit = (e) => {                   // معالج الحدث يستقبل SyntheticEvent
    e.preventDefault();                              // منع إعادة تحميل الصفحة الافتراضي
    e.stopPropagation();                             // منع صعود الحدث للعناصر الأب
    onSearch(e.target.query.value);                  // قراءة القيمة وتنفيذ البحث
  };                                                 // نهاية المعالج
  return <form onSubmit={handleSubmit}>...</form>; // ربط المعالج بـ onSubmit
}                                                    // نهاية المكون

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
// خطأ فادح: استدعاء الدالة فوراً أثناء الـ Render بدلاً من تمرير مرجعها
<button onClick={deleteUser(user.id)}>
  حذف المستخدم
</button> <!-- سيتم تنفيذ الحذف فور رسم الصفحة والدخول في حلقة لانهائية! -->
✅ الحل الهندسي القياسي (Best Practice)
// الحل الصحيح: تمرير دالة سهمية تستدعي الحذف عند الضغط الفعلي
<button onClick={() => deleteUser(user.id)}>
  حذف المستخدم
</button>

التشخيص الهندسي: كتابة الأقواس () بعد اسم الدالة داخل JSX يؤدي لتنفيذها في مرحلة الـ Render فوراً وليس عند ضغط المستخدم، مما يسبب أخطاء State updates أثناء العرض.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

سؤال إنترفيو للمهندسين الكبار: كيف تحل مشكلة صعود الحدث (Event Bubbling) عندما تضغط على زرار داخل بطاقة Card قابلة للنقر بالكامل؟

الحل المعماري هو استدعاء e.stopPropagation() داخل معالج حدث الزرار الداخلي لمنع وصول حدث الـ Click إلى البطاقة الأم (Card Container). وفي بعض الحالات المعقدة التي تشمل مكونات منبثقة (Portals / Modals)، يجب تذكر أن أحداث ريآكت تصعد عبر شجرة مكونات React Tree حتى لو كان العنصر مرسوماً في مكان آخر في شجرة الـ DOM الحقيقية.
