Performance Optimization: useMemo, useCallback, React.memo & React 19 Compiler

تحسين الأداء المتقدم: useMemo، useCallback، React.memo ومترجم React 19 Compiler

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم معضلة تطابق المراجع (Referential Equality) ولماذا تعيد ريآكت رسم المكونات الفرعية.
  • التفريق الصارم بين useMemo (لحفظ نواتج العمليات الحسابية) و useCallback (لتثبيت مراجع الدوال).
  • تطبيق React.memo لمنع إعادة رسم المكونات النقية عند ثبات الـ Props.
  • فهم دور المترجم الجديد React 19 Compiler وكيف يلغي الحاجة للميموزيشن اليدوي مستقبلاً.

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

في جافاسكريبت، {} !== {} و (() => {}) !== (() => {}). كل مرة يتم فيها استدعاء دالة المكون في ريآكت، يتم إنشاء دوال وكائنات جديدة تماماً في الذاكرة بعناوين مراجع مختلفة. عندما تمرر دالة مثل handleClick لمكون فرعي مغلف بـ React.memo، يعتقد المكون الفرعي أن الخصائص قد تغيرت لأن مرجع الدالة جديد، فيعيد رسم نفسه بالكامل (Unnecessary Re-render) مهدراً وقت المعالج! هنا يأتي دور أدوات التثبيت الذاكري (Memoization): - useCallback: لتثبيت مرجع الدالة وحمايته من إعادة الإنشاء. - useMemo: لتخزين نتيجة عملية حسابية ثقيلة (مثل فلترة 50 ألف سجل) وعدم إعادتها إلا إذا تغيرت مصفوفة الاعتماديات (Dependencies). - React.memo: لمنع إعادة رسم المكون النقي طالما أن خصائصه متطابقة. في هذا الدرس، هنتعلم متى يكون الـ Memoization ضرورياً ومفتاحاً لسرعة التطبيق، ومتى يكون "تحسيناً سابقاً لأوانه" (Premature Optimization) يزيد من استهلاك الذاكرة، وما هي ثورة **React Compiler** الجديدة في ريآكت 19.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

01

مبدأ الـ Referential Equality في ريآكت

ريآكت تعتمد على المقارنة السطحية Object.is(prevProp, nextProp)؛ الدوال والكائنات المنشأة في الـ Render تفشل في هذا الاختبار دائماً ما لم تثبت.

02

تثبيت العمليات الحسابية الثقيلة بـ useMemo

تغليف العمليات الحسابية المعقدة (Sorting/Filtering) بـ useMemo(() => compute(data), [data]) لعدم تشغيلها في كل Render.

03

تثبيت مراجع الدوال بـ useCallback

تثبيت مرجع الدالة الممررة لمكونات React.memo أو المضمنة في مصفوفة اعتماديات useEffect.

04

حماية المكونات النقية بـ React.memo

تغليف المكون بـ React.memo(MyComponent) لتخطي عملية الـ Diffing إذا كانت الـ Props متطابقة سطحياً.

05

عصر الـ React 19 Compiler (Forget Memoization)

المترجم الجديد يحلل شجرة الـ AST ويثبت المراجع تلقائياً على مستوى كود التجميع بدون كتابة useMemo/useCallback يدوياً.

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لأن الـ Memoization ليس مجانياً! كل استدعاء لـ useMemo يحجز مساحة في الذاكرة لتخزين مصفوفة الاعتماديات السابقة والقيمة المحفوظة، ويجبر ريآكت على إجراء مقارنات دورية في كل Render. إذا كانت العملية الحسابية بسيطة (مثل a + b)، فإن تكلفة الـ Memoization تكون أعلى من تكلفة إعادة الحساب المباشرة!

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

const filteredList = useMemo(() => {              // تثبيت نتيجة الحساب الثقيل
  return items.filter(i => i.price > minPrice).sort((a, b) => a.id - b.id); // عمليات معالجة مصفوفة ضخمة
}, [items, minPrice]);                               // إعادة الحساب فقط عند تغير items أو minPrice
const handleSelect = useCallback((id) => {        // تثبيت مرجع الدالة
  setSelectedId(id);                                 // تحديث الحالة
}, []);                                              // مصفوفة فارغة تعني مرجع ثابت للأبد
export const Row = React.memo(function Row({ item, onSelect }) { ... }); // مكون نقي محمي من إعادة الرسم

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
// خطأ شائع: تمرير مصفوفة اعتماديات ناقصة في useCallback
const handleAdd = useCallback(() => {
  setItems([...items, newItem]); // items غير مدرجة في الـ deps!
}, []); // سيتسبب في Stale Closure ويقرأ مصفوفة قديمة دائماً
✅ الحل الهندسي القياسي (Best Practice)
// الحل الأمثل: استخدام Functional State Update
const handleAdd = useCallback((newItem) => {
  setItems(prevItems => [...prevItems, newItem]); // لا يعتمد على items الخارجية
}, []); // مصفوفة فارغة آمنة تماماً بدون Stale Closures

التشخيص الهندسي: الاعتماديات غير المعلنة داخل مصفوفة الـ Dependencies تتسبب في ظاهرة Stale Closures حيث تحتفظ الدالة بنسخ قديمة من المتغيرات من الدورة الأولى ولا تستشعر التحديثات الجديدة.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

سؤال إنترفيو للمهندسين الكبار: كيف تكتب دالة مقارنة مخصصة arePropsEqual لـ React.memo(Component, arePropsEqual) ومتى تكون ضرورية؟

دالة arePropsEqual تستقبل (prevProps, nextProps) وتُرجع true إذا كانت الخصائص متطابقة ويجب تخطي الرسم، أو false إذا تغيرت ويجب إعادة الرسم (عكس shouldComponentUpdate تماماً). نلجأ لكتابة دالة مخصصة عندما يحتوي المكون على كائن معقد أو مصفوفة تتغير مراجعها باستمرار ولكننا نهتم بمقارنة حقل واحد محدد فقط (مثل prevProps.user.id === nextProps.user.id).
