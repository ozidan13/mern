Component Architecture: Compound Components, Render Props & Polymorphic Elements

أنماط معمارية المكونات: المكونات المركبة (Compound Components) والعناصر المتعددة الأشكال (as Prop)

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • بناء واجهات مستخدم معقدة ومرنة باستخدام نمط المكونات المركبة (Compound Components Pattern).
  • مشاركة الحالة بين المكونات المتداخلة ضمنياً عبر React Context الداخلي.
  • بناء مكونات مرنة متعددة الأشكال (Polymorphic Components) تدعم خاصية as="button" | as="a".
  • تطبيق مبدأ المسؤولية الواحدة (Single Responsibility Principle) وفصل مكونات العرض (Presentational) عن المنطق (Container).

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

عندما يبدأ أي مشروع ريآكت، تكون المكونات بسيطة. لكن مع نمو التطبيق وتراكم متطلبات التصميم، يتحول المكون البسيط (مثل <Select /> أو <Modal />) إلى وحش برمجى يعاني من "تضخم الخصائص" (Props Explosion / Prop Apocalypse)! تجد المطور يمرر 25 prop مختلف: showIcon, iconPosition, headerTitle, footerButtons, onHeaderClick... كود صلب، غير مرن، وأي تعديل بسيط في التصميم يجبرك على تعديل المكون الأصلي وإضافة المزيد من الخصائص! الحل الهندسي المعتمد في كبرى مكتبات الواجهات العالمية (مثل Radix UI و Headless UI و Shadcn) هو نمط **المكونات المركبة (Compound Components)** مثل: 

<Select value={val} onChange={setVal}>
  <Select.Trigger />
  <Select.Content>
    <Select.Item value="1">Option 1</Select.Item>
  </Select.Content>
</Select>
في هذا الدرس، هنتعلم إزاي نبني مكتبة مكونات احترافية مرنة، تشارك حالتها الداخلية بسلاسة عبر Context معزول، وتمنح المطورين حرية كاملة في تخصيص الهيكل البصري.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

01

تصميم سياق المكون المركب المعزول

إنشاء Context خاص محلي بالمكون الأم لتخزين الحالة المشتركة (مثل isOpen و activeIndex) ودوال التبديل.

02

بناء المكونات الفرعية التابعة (Sub-components)

تفكيك الواجهة إلى قطع مستقلة: Trigger للفتح/الإغلاق، Content للحاوية، و Item للعناصر الفردية.

03

ربط المكونات عبر الـ Namespaces

ربط المكونات الفرعية كخصائص ساكنة على المكون الأم Accordion.Item = AccordionItem لتسهيل الاستيراد والتنظيم.

04

المكونات متعددة الأشكال (Polymorphic as Prop)

دعم خاصية as={Link} أو as="button" للسماح للمكون بتغيير الوسم الأساسي مع الحفاظ على التنسيقات والسلوك.

05

حماية المكونات بحراس السياق (Context Guards)

رمي خطأ واضح إذا تم استخدام المكون الفرعي خارج الحاوية الأم المخصصة له لضمان سلامة الاستخدام.

🤔 سؤال تحدي كبار المهندسين:

ما هي فائدة استخدام خاصية asChild المعتمدة في مكتبة Radix UI بدلاً من خاصية as التقليدية في المكونات المركبة؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

خاصية asChild تطبق نمط الـ Slot Pattern: بدلاً من إنشاء وسم جديد وتمرير الـ props له، تقوم بدمج الـ props ومعالجات الأحداث والـ Refs الخاصة بالمكون مباشرة في العنصر الابن الوحيد الممرر له (CloneElement with Merged Props)، مما يمنح المطور تحكماً كاملاً بنسبة 100% في شجرة الـ DOM بدون أي حاويات وسيطة.

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

const AccordionContext = createContext(null);        // إنشاء سياق معزول
export function Accordion({ children, defaultOpen = null }) { // المكون الحاوي الأم
  const [openId, setOpenId] = useState(defaultOpen); // الحالة المشتركة الداخلية
  return (                                           // توفير السياق
    <AccordionContext.Provider value={{ openId, setOpenId }}> // توزيع الحالة والتحكم للأبناء
      <div className="accordion-root">{children}</div> // هيكل الحاوية
    </AccordionContext.Provider>               // نهاية المزود
  );                                                 // نهاية المكون الأم
}                                                    // نهاية الدالة

<Modal open={open} onOpenChange={setOpen}>

  </Modal.Header>
  <Modal.Body>
    <ProfileForm />
  </Modal.Body>
  <Modal.Footer>

  </Modal.Footer>
</Modal>

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

سؤال إنترفيو للمهندسين الكبار: كيف تطبق TypeScript Generics مع Polymorphic Components لضمان صحة الـ Type Checking للـ Props المخصصة (مثل href لـ a و type لـ button)؟

نستخدم نمط Polymorphic Component Type في TypeScript: نحدد نوع المكون كـ Generic ، ونعرف الـ Props بـ React.ComponentPropsWithoutRef & { as?: E }. هذا يضمن أنك لو مررت as="a"، سيجبرك المحرر على تمرير href ويقترح خصائص الروابط فقط، ولو مررت as="button"، سيقترح type="submit" ويمنع تمرير href، محققاً Type Safety مطلقاً على مستوى الـ Compile Time.
