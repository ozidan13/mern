Advanced Component Patterns: Compound Components & Render Props

أنماط المكونات المتقدمة: المكونات المركبة ودوال العرض (Render Props)

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • بناء مكونات مركبة (Compound Components) تشارك الحالة عبر Context API ضمنياً.
  • تطبيق نمط Render Props لفصل منطق الحالة عن طريقة العرض المرئي.
  • إتقان المكونات متعددة الأشكال (Polymorphic Components مع خاصية as).

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

المكونات المعقدة مثل القوائم المنسدلة (Dropdowns) والـ Modals والـ Accordions تصبح غير قابلة للصيانة إذا حاولت تمرير 20 prop لمكون واحد ضخم (Mega-Component). نمط المكونات المركبة (Compound Components) يتيح بناء واجهات مرنة ومقسمة تشارك الحالة ضمنياً مثل عناصر

كيف يتم ربط المكونات الفرعية بالأب في نمط Compound Components؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

إما بتعيينها كخصائص ساكنة مثل Tabs.List = TabList أو تصديرها معاً ومشاركتها لـ Context داخلي.

تشريح الكود سطراً بسطر · Code Anatomy

1: <Tabs defaultValue="account">             // المكون الأب الحافظ للحالة
2:   <Tabs.List><Tabs.Tab value="account">Account</Tabs.Tab></Tabs.List> // المكونات الفرعية
3:   <Tabs.Panel value="account"><Profile /></Tabs.Panel> // لوحة المحتوى
4: </Tabs>                                   // إغلاق المكون المركب

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
<Select isMulti hasSearch allowCreate showIcons ... 30 props />
✅ الحل الهندسي الصحيح (Best Practice)
<Select><Select.Search /><Select.Options /></Select>

التشخيص الهندسي: تمرير عشرات الـ Props ينشئ كوداً غير مرن، بينما المكونات المركبة تعطي مرونة تامة.
