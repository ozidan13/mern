JSX Under the Hood: React.createElement, Compilation & React 19 JSX Transform

تشريح الـ JSX: دالة React.createElement ومحول JSX الحديث في ريآكت 19

  • حماية التطبيقات من هجمات Cross-Site Scripting (XSS) بفهم كيفية قيام JSX بتطهير النصوص.

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

الكثير من المطورين يعتقدون أن JSX هو "كتابة كود HTML داخل كود JavaScript". هذه الفكرة خاطئة تماماً وتقود إلى سوء فهم مستمر لكيفية عمل ريآكت! الـ JSX ليس HTML وليس نصاً برمجياً يفهمه المتصفح مباشرة. المتصفح لا يستطيع قراءة <h1 className="title">Hello</h1> وسيرمي فوراً خطأ SyntaxError. الـ JSX هو في الحقيقة مجرد "صيغة مختصرة ومريحة" (Syntactic Sugar) لكتابة استدعاءات دوال تنتج كائنات جافاسكريبت عادية اسمها React Elements. عندما تكتب وسماً بسيطاً، يقوم المترجم (مثل SWC أو Babel) بتحويله إلى كائن يحتوي على { type: 'h1', props: { className: 'title', children: 'Hello' } }. في هذا الدرس، هنفكك محرك الـ JSX، وهنعرف إزاي ريآكت 19 بتتعامل مع الـ JSX Transform الجديد، ولماذا كل عنصر في JSX يملك حقلاً سرياً $$typeof: Symbol(react.element) لحماية تطبيقك من الاختراق.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

01

مرحلة الترجمة (Compile Phase)

يقوم المترجم بتحويل كل وسم JSX إلى استدعاء _jsx() من مكتبة react/jsx-runtime مع فصل الخصائص والمحتويات (Children).

02

إنشاء كائن العنصر (React Element Object)

تُرجع الدالة كائناً بسيطاً (Plain JS Object) يصف الشجرة البصرية: type (نوع العنصر)، props (الخصائص)، و key للتعرف عليه.

03

درع الأمان الأمني ($$typeof Symbol Shield)

ريآكت تضع Symbol خاصاً $$typeof على كل عنصر لمنع هجمات XSS وحظر معالجة كائنات JSON خبيثة قادمة من السيرفر.

04

قواعد التقييم المعجمي (Expressions in Curly Braces)

أي شيء يوضع داخل أقواس {} يتم تقييمه كـ JavaScript Expression (مثل ternary operators أو array.map) ولا يقبل statements مثل if أو for.

05

الوسوم المجهولة والـ React Fragments (<>)

استخدام Fragment لتجميع عناصر متعددة دون إضافة وسوم div غير ضرورية إلى شجرة الـ DOM الحقيقية.

لماذا تمنع ريآكت كتابة class بدلاً من className و for بدلاً من htmlFor في وسوم JSX؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لأن JSX يُترجم إلى كود جافاسكريبت خالص، وكلمتا class و for هما كلمات محجوزة (Reserved Keywords) في لغة JavaScript. ولتجنب الاصطدام مع قواعد اللغة، اعتمدت ريآكت خصائص الـ DOM Properties القياسية مثل className و htmlFor.

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

import { jsx as _jsx } from "react/jsx-runtime";     // المحول التلقائي في React 19
function Greeting({ name }) {                        // مكون دالي يستقبل props
  return _jsx("h1", {                                // الترجمة الفعلية لوسم JSX
    className: "welcome-title",                      // الخصائص الممررة
    children: `Hello, ${name}!`                      // المحتوى النصي كـ children
  });                                                // نهاية الاستدعاء
}                                                    // نهاية المكون

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
// خطأ شائع: محاولة إرجاع عناصر متجاورة بدون Fragment
function UserCard() {
  return (
    <h2>Sarah</h2>
    <p>Software Engineer</p>
  ); // خطأ SyntaxError: JSX expressions must have one parent element
}
✅ الحل الهندسي القياسي (Best Practice)
// الحل الهندسي: استخدام React Fragment
function UserCard() {
  return (
    <>
      <h2>Sarah</h2>
      <p>Software Engineer</p>
    </>
  ); // تجميع العناصر بدون توليد div إضافي في المتصفح
}

التشخيص الهندسي: دوال جافاسكريبت لا يمكن أن تُرجع قيمتين في نفس الوقت return A, B. بما أن JSX يترجم إلى استدعاء دالة، يجب تغليف العناصر في جذر أب واحد أو استخدام Fragment.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

سؤال إنترفيو للمهندسين الكبار: ما هو الفرق بين Automatic JSX Transform المقدم في React 17/19 ومحول Classic JSX القديم؟

في المحول القديم، كان كل وسم JSX يُترجم إلى React.createElement، وكان من الإلزامي كتابة import React from "react" في كل ملف. في المحول الجديد Automatic JSX Transform، يقوم المترجم باستيراد دوال متخصصة _jsx() تلقائياً من react/jsx-runtime. هذا يقلل حجم حزمة الـ Bundle بنسبة طفيفة، ويحسن أداء إنشاء العناصر، ويسمح بتمرير الخصائص بشكل أسرع دون التحقق غير الضروري من defaultProps.
