1. Core Concept & Mechanics · الفكرة الأساسية

Real-Life Analogy · تشبيه مراجعة وتعديل مسودة الكتاب

تخيّل كاتباً يريد تعديل فقرة واحدة في كتاب من 500 صفحة: إعادة طباعة وتجليد الكتاب بالكامل في كل مرة هو تماماً ما يحدث عند تعديل الـ DOM الحقيقي مباشرة (بطيء ومكلف جداً). بدلاً من ذلك، يحتفظ الكاتب بـ مسودة رقمية خفيفة على شاشة الحاسوب (Virtual DOM): يقارن المسودة القديمة بالجديدة، ويحدد فقط السطر الذي تغير (Diffing)، ثم يرسل للمطبعة أمراً بتعديل ذلك السطر فقط في النسخة المطبوعة النهائية (DOM Commit)!

Definition & Purpose

Reconciliation is the algorithm React uses to diff two trees of elements to determine which parts need to be updated in the host environment (the real DOM). By assuming elements of different types generate different trees and tracking identity with key props, React reduces tree diffing complexity from $O(n^3)$ to $O(n)$.

عملية المطابقة (Reconciliation) هي الخوارزمية الذكية التي يقارن بها React شجرتين من شجرة الـ Virtual DOM لتحديد أقل عدد ممكن من التعديلات الواجب تطبيقها على الـ DOM الحقيقي، مما يضمن أداءً فائق السرعة حتى في أضخم الواجهات.

The Two Golden Rules of Diffing · قاعدتا المقارنة الذهبيتان

1
1. Elements of Different Types are Destroyed

إذا تغير نوع العنصر (مثلاً من <div> إلى <p>)، يحذف React الشجرة القديمة بالكامل ويشيد شجرة جديدة من الصفر مع تدمير كل الـ State بداخلها.

2
2. Keys Preserve Identity Across Re-orders

في القوائم والمصفوفات، يستخدم React خاصية key الفريدة لتتبع حركة العناصر ومعرفة أي عنصر تم نقله، حذفه، أو إضافته بدلاً من إعادة إنشائها جميعاً.

Predict Before You Run · توقّع النتيجة أولاً

Why is using array index as a key dangerous when items can be inserted at the top of a list?

لماذا يعتبر استخدام مؤشر المصفوفة (index) كـ Key خطيراً عند إضافة عنصر في بداية القائمة؟

لأن إضافة عنصر في البداية يغير index جميع العناصر التالية! فيعتقد React أن جميع العناصر قد تغيرت ويعيد رسم كل مدخلات الحقول (Form inputs) وحالاتها بشكل خاطئ.

5. Deep Dive & Complexity Analysis · التحليل والتعقيد

Heuristic Diffing Complexity
O(N) Linear Time

بفضل افتراضات React المبنية على نوع العنصر والمفاتيح، تتم المقارنة في زمن خطي بدلاً من $O(N^3)$.

Fiber Double Buffering
2x Tree Memory

يحتفظ React بشجرتين في الذاكرة: الشجرة الحالية (Current) وشجرة العمل قيد التجهيز (WorkInProgress).

Render Phase vs Commit Phase in React 19
Phase Nature Can be Interrupted? Side Effects Allowed?
Render Phase Pure computation & VDOM diffing Yes (Concurrent features) No (Must be pure)
Commit Phase Direct real DOM mutations No (Must be synchronous) Yes (LayoutEffects / DOM refs)

6. Practice & Common Mistakes · أخطاء شائعة

Random Keys on Every Render (Math.random())
// ❌ DISASTROUS (Destroys DOM and State every render)
<Item key={Math.random()} />
// ✅ STABLE (Maintains identity and DOM node reuse)
<Item key={item.id} />

التشخيص: توليد مفتاح عشوائي في كل دورة رسم يجبر React على تدمير المكون والـ DOM بالكامل في كل تحديث مما يدمر الأداء وتجربة المستخدم.

8. Production Notes & Interviews · في بيئة العمل والمقابلات

Interview Question: React 19 Compiler vs Virtual DOM

Q: Does React 19 eliminate the Virtual DOM?

الإجابة: كلا! الـ Virtual DOM وشجرة الـ Fiber لا تزالان قلب محرك ريآكت. ما يقدمه الـ React 19 Compiler هو التحسين التلقائي للتخزين المؤقت (Auto-memoization)، مما يقلل عدد عمليات إعادة حساب الدوال دون إلغاء نموذج الـ Virtual DOM نفسه.
