Prisma Transactions: Sequential Batching vs Interactive $transaction

معاملات بريزما: التجميع المتسلسل والمعاملات التفاعلية ($transaction)

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • استخدام مصفوفة prisma.$transaction([q1, q2]) للعمليات المستقلة السريعة.
  • استخدام Interactive Transactions: prisma.$transaction(async (tx) => { ... }).
  • ضبط خيارات المعاملة: timeout و maxWait ومستويات العزل (Isolation Levels).

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

عند تنفيذ عمليات بنكية أو إنشاء طلب وشراء منتجات وتخفيض المخزون، يجب ضمان تنفيذ جميع العمليات معاً أو التراجع عنها بالكامل. يوفر بريزما نوعين من المعاملات: مصفوفة المعاملات المتسلسلة Sequential $transaction السريعة، والمعاملات التفاعلية Interactive $transaction التي تتيح قراءة البيانات واستخدامها في الشروط قبل اتخاذ قرار الحفظ أو التراجع.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
المعاملات المتسلسلة (Array Batching)

تمرير مصفوفة استعلامات تنفذ في معاملة SQL واحدة بأعلى سرعة.

2
المعاملات التفاعلية (Interactive Callback)

الحصول على كائن عميل مخصص (tx) لقراءة وتعديل البيانات بناءً على شروط منطقية.

3
التراجع التلقائي عند الخطأ

إذا رُمي أي استثناء داخل الدالة، يقوم بريزما بعمل ROLLBACK فوري وتحرير الأقفال.

🤔 سؤال تحدي المهندسين:

ما هي مشكلة استخدام كائن prisma العام بدلاً من كائن tx داخل دالة Interactive Transaction؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

استخدام prisma العادي ينفذ الاستعلام خارج نطاق المعاملة في اتصال منفصل؛ لضمان شمول العملية داخل المعاملة والتراجع عند الفشل، يجب دائماً استخدام كائن tx الممرر للمعاملة.

تشريح الكود سطراً بسطر · Code Anatomy

1: await prisma.$transaction(async (tx) => {    // بدء معاملة تفاعلية
2:   const sender = await tx.account.update({ ... }); // استخدام كائن tx الإلزامي
3:   const receiver = await tx.account.update({ ... }); // استخدام كائن tx الإلزامي
4: }, { maxWait: 5000, timeout: 10000 });          // ضبط مهلة الانتظار

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
await prisma.$transaction(async (tx) => { await prisma.user.update(...); }); /* خطأ: استخدام prisma بدلاً من tx */
✅ الحل الهندسي الصحيح (Best Practice)
await prisma.$transaction(async (tx) => { await tx.user.update(...); }); /* صحيح ومشمول في المعاملة */

التشخيص الهندسي: استدعاء prisma العادي يخرج العملية من المعاملة ويفقد حماية التراجع التلقائي (Rollback).

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): ما هي خيارات maxWait و timeout في معاملات بريزما وفيمَ تفيد؟

الـ `maxWait` هو أقصى وقت ينتظره بريزما للحصول على اتصال متاح من مجمع الاتصالات لبدء المعاملة (افتراضياً 2 ثانية). والـ `timeout` هو أقصى وقت مسموح به لتنفيذ كود المعاملة بالكامل قبل إلغائها وعمل Rollback تلقائي (افتراضياً 5 ثوانٍ) لمنع تعليق الأقفال في قاعدة البيانات.
