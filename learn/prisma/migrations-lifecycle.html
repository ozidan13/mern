Prisma Migrate: prisma migrate dev, deploy, reset & The Shadow Database

دورة حياة الهجرات في بريزما: الهجرة الآمنة، النشر وقاعدة البيانات الظلية (Shadow DB)

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • إتقان أوامر الهجرة: prisma migrate dev (للتطوير)، prisma migrate deploy (للإنتاج).
  • فهم دور الـ Shadow Database في كشف أخطاء تضارب الهجرات (Migration Drift).
  • تخصيص ملفات الهجرة بـ --create-only لإضافة أوامر SQL متقدمة (Triggers, Views).

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

تعديل مخطط قاعدة البيانات في بيئة الإنتاج بدون أدوات هجرة معيارية هو مخاطرة بتدمير وفقدان بيانات العملاء الحية! أداة Prisma Migrate تدير تاريخ التعديلات عبر ملفات SQL حقيقية قابلة للتتبع في Git. في هذا الدرس سنفهم كيف تستخدم بريزما قاعدة بيانات ثانية مؤقتة تُسمى Shadow Database للتأكد من سلامة ملفات الهجرة قبل لمس قاعدة البيانات الحقيقية.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
الهجرة في بيئة التطوير (migrate dev)

مقارنة schema.prisma مع قاعدة البيانات وإنشاء ملف SQL جديد وترقية الجداول وتوليد عميل الـ TypeScript.

2
التحقق عبر الـ Shadow Database

تطبيق كل ملفات الهجرة التاريخية من الصفر في داتابيز مؤقتة للتأكد من عدم وجود أي تضارب.

3
النشر في الإنتاج (migrate deploy)

تطبيق ملفات الهجرة الجديدة المعلقة فقط دون توليد ملفات جديدة ودون الحاجة لـ Shadow DB.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

لماذا يحظر استخدام prisma migrate dev في خوادم الإنتاج والـ CI/CD؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لأن prisma migrate dev تفترض وجود بيئة تفاعلية؛ وإذا اكتشفت أي عدم تطابق (Schema Drift) قد تقترح إعادة ضبط وحذف قاعدة البيانات (Database Reset) مما يؤدي لحذف كل بيانات الإنتاج فوراً! في الإنتاج نستخدم prisma migrate deploy حصرياً.

تشريح الكود سطراً بسطر · Code Anatomy

1: # Development Migration Command                 // أمر التطوير
2: npx prisma migrate dev --name add_orders_table  // إنشاء وتطبيق ملف SQL وتحديث العميل
3: # Production Deployment Command                 // أمر الإنتاج الآمن
4: npx prisma migrate deploy                       // تطبيق الهجرات المعلقة فقط بدون مساس بالبيانات

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
استخدام npx prisma db push في الإنتاج بدلاً من prisma migrate deploy!
✅ الحل الهندسي الصحيح (Best Practice)
استخدام prisma migrate dev محلياً و prisma migrate deploy في الإنتاج

التشخيص الهندسي: أمر db push لا يسجل تاريخ الهجرات في جدول _prisma_migrations وقد يحذف أعمدة حية بدون تحذير.

خلاصة بيئة العمل وأسئلة المقابلات · Production Recap & Senior Notes

Database Migrations
النمط المعماري الأساسي المعتمد في المنظومة.
Prisma 5.x/6.x
المعيار الإنتاجي المعتمد لبيئات العمل الحديثة.
💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): ما هي الـ Shadow Database في بريزما ولماذا تفشل الهجرة إذا لم يمتلك المستخدم صلاحية إنشاء قواعد بيانات؟

الـ Shadow Database هي قاعدة بيانات مؤقتة تنشئها بريزما تلقائياً أثناء `migrate dev` للتحقق من عدم حدوث تعارضات واكتشاف انحراف المخطط (Schema Drift)؛ إذا لم يكن لمستخدم الـ SQL صلاحية `CREATEDB` تفشل العملية ما لم يتم توفير رابط داتابيز ظلية يدوية عبر `shadowDatabaseUrl`.
