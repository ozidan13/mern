Raw SQL Escape Hatches: $queryRaw, $executeRaw & SQL Template Tags

استعلامات SQL الخام في بريزما: دوال $queryRaw وتأمين قوالب الـ SQL Tagged

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • تنفيذ استعلامات القراءة المتقدمة باستخدام prisma.$queryRaw واستعلامات التعديل بـ $executeRaw.
  • فهم كيفية عمل Template Tags في تحويل المتغيرات لمعاملات مجهزة (Prepared Statements ($1, $2)).
  • استخدام Prisma.raw بحذر شديد للمعرفات الديناميكية وأسماء الجداول.

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

مهما كانت قوة الـ ORM، هناك دائماً استعلامات SQL متقدمة ومخصصة (مثل استعلامات الجداول الجغرافية PostGIS أو دوال النوافذ المتقدمة أو تقارير الـ Full-Text Search المعقدة) التي لا يدعمها الـ API التجريدي. يوفر بريزما منافذ هروب للـ SQL النقي عبر prisma.$queryRaw مع حماية حديدية مدمجة ضد هجمات SQL Injection بفضل وسوم القوالب Prisma.sql.

🤔 سؤال تحدي المهندسين:

ما هو الخطر الفادح لاستخدام prisma.$queryRawUnsafe() بدلاً من prisma.$queryRaw مع مدخلات المستخدم؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

الدالة $queryRawUnsafe تدمج النصوص مباشرة دون تحويلها إلى Prepared Parameters؛ إذا مررت لها نصوصاً قادمة من المستخدم ستكون قاعدة بياناتك عرضة لهجمات SQL Injection واختراق البيانات بالكامل.

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
prisma.$queryRawUnsafe(`SELECT * FROM users WHERE id = ${req.body.id}`); /* ثغرة SQL Injection! */
✅ الحل الهندسي الصحيح (Best Practice)
prisma.$queryRaw`SELECT * FROM users WHERE id = ${req.body.id}`; /* محمي تلقائياً */

التشخيص الهندسي: استخدام $queryRawUnsafe مع دمج النصوص يلغي المعاملات المجهزة ويفتح الباب لاختراق السيرفر.

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): متى تضطر لاستخدام Prisma.raw() وكيف تضمن أمانه ضد الاختراق؟

نستخدم `Prisma.raw()` عندما نحتاج لتمرير اسم جدول أو عمود ديناميكياً (لأن أسماء الجداول لا يمكن تمريرها كـ SQL Parameters)؛ ولضمان الأمان، يجب فحص اسم الجدول مسبقاً ومطابقته لقائمة بيضاء صارمة من الثوابت (Whitelist Enum) لمنع تمرير أي نص مريب.
