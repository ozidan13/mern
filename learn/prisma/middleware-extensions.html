Prisma Client Extensions: Query, Model, Result & Client Methods

توسيعات عميل بريزما (Prisma Client Extensions): تعديل النتائج والحذف الناعم

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم أنواع التوسيعات الأربعة: model, result, query, client.
  • بناء نظام الحذف الناعم (Soft Delete Extension) باعتراض استعلامات delete و findMany.
  • إضافة حقول ديناميكية محسوبة عبر result extension مع دعم TypeScript التلقائي.

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

في إصدارات بريزما القديمة، كان تخصيص السلوك يتم عبر Middleware قديم محدود القدرات. في بريزما الحديثة، تم استبداله بنظام Prisma Client Extensions ($extends) الثوري. تتيح لك التوسيعات إضافة دوال مخصصة لنماذجك (Custom Model Methods)، حساب حقول جديدة تلقائياً عند القراءة (Computed Result Fields)، واعتراض الاستعلامات لتطبيق الحذف الناعم (Soft Delete) وعزل المستأجرين (Multi-Tenancy) تلقائياً!

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
توسيع النتائج (Result Extensions)

إضافة خصائص محسوبة لحظياً (مثل fullName) تظهر تلقائياً في نتائج كل استعلام.

2
اعتراض الاستعلامات (Query Extensions)

تعديل جمل الاستعلام تلقائياً لحقن { where: { deletedAt: null } } في كل عمليات البحث.

3
إعادة استخدام التوسيعات كحزم (Modular Extensions)

تصدير التوسيعات كدوال نقية وتركيبها معاً عبر prisma.$extends(ext1).$extends(ext2).

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

توسيعات بريزما (Extensions) تقوم بتوليد وتحديث أنواع الـ TypeScript المعادة تلقائياً؛ فإذا أضفت حقل fullName عبر result extension، سيتعرف محرر VS Code عليه فورياً في كائن النتيجة مع الإكمال التلقائي.

تشريح الكود سطراً بسطر · Code Anatomy

1: const prisma = new PrismaClient().$extends({    // توسيع العميل
2:   result: {                                     // توسيع النتائج
3:     user: {                                     // نموذج المستخدم
4:       fullName: { needs: { firstName: true, lastName: true }, // الحقول المطلوبة
5:         compute(u) { return `${u.firstName} ${u.lastName}`; } } // الدالة المحسوبة
6:     }                                           // نهاية النموذج
7:   }                                             // نهاية التوسيع
8: });                                             // العميل الموسع جاهز

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
استخدام $use (Middleware القديم) الملغي في مشاريع بريزما الحديثة
✅ الحل الهندسي الصحيح (Best Practice)
استخدام $extends لإنشاء وحدات توسيع حديثة متوافقة بالكامل مع TypeScript

التشخيص الهندسي: الـ Middleware القديم تم استبعاده لأنه لا يدعم تعديل الـ TypeScript Types ويفقد مرونة البناء.

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): كيف تنفذ معمارية التعددية الإيجارية (Multi-Tenancy Architecture) تلقائياً باستخدام Prisma Extensions؟

ننشئ `query extension` يعترض كل استعلامات النماذج التابعة للشركات؛ حيث يقوم بقراءة `tenantId` من سياق الطلب الحالي (عبر `AsyncLocalStorage`) ويحقن تلقائياً شرط `where: { tenantId }` في كل استعلامات القراءة والكتابة، مما يمنع تسريب بيانات شركة لأخرى برمجياً بنسبة 100% دون كتابة الشرط يدوياً في كل مسار.
