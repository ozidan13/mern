Nested Relations, Deep Querying: include vs select & Fluent API

العلاقات المتداخلة في بريزما: مقارنة include و select والاستعلامات العميقة

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • بناء العلاقات 1:1 و 1:N و N:M في مخطط بريزما وفهم جداول الربط التلقائية (Implicit Many-to-Many).
  • التمييز الصارم بين include (لجلب العلاقات كاملة) و select (لتحديد الحقول المطلوبة حصراً).
  • تطبيق التصفية المتقدمة على العلاقات المتداخلة (some, every, none).

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

في قواعد البيانات العلائقية، جلب المستخدم مع مقالاته وملفه الشخصي وتعليقاته يتطلب كتابة استعلامات JOIN معقدة. بريزما تقدم طريقة مذهلة: الاستعلامات المتداخلة (Nested Queries). لكن الفخ الأكبر هو استخدام include الذي يسحب كل أعمدة الجدول بما فيها الحقول الحساسة (مثل كلمات السر المحروقة)، بينما يوفر select دقة متناهية لاختيار الأعمدة المطلوبة فقط.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

1

العلاقات كثيرة لكثير الضمنية (Implicit M:N)

بريزما تنشئ وتدير جدول الربط الوسيط في قاعدة البيانات تلقائياً دون الحاجة لنمذجة يدوية.

2

التحديد الدقيق بـ select

حماية البيانات الحساسة وجلب id و name فقط من المستخدم مع أسماء المقالات.

3

مشغلات العلاقات (some, every, none)

جلب المستخدمين الذين لديهم مقال واحد على الأقل منشور (posts: { some: { published: true } }).

🤔 سؤال تحدي كبار المهندسين:

هل يمكنك استخدام include و select معاً في نفس مستوى الاستعلام في عميل بريزما؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لا، يحظر استخدام include و select معاً في نفس مستوى الكائن؛ إما أن تستخدم include لجلب كل الحقول + العلاقات، أو تستخدم select وتحدد الحقول والعلاقات بداخلها بدقة.

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

1: const user = await prisma.user.findUnique({       // استعلام علاقات متداخلة
2:   where: { email: "amr@codehub.dev" },            // الشرط
3:   select: {                                       // تحديد دقيق للأعمدة
4:     id: true, name: true,                         // حقول المستخدم
5:     posts: { where: { published: true }, select: { title: true } } // تصفية وتحديد حقول المقالات
6:   }                                               // نهاية الاستعلام
7: });                                               // النتيجة مشفرة بأنواع TypeScript دقيقة

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
const user = await prisma.user.findUnique({ include: { posts: true } }); /* يسرب password_hash للمتصفح! */
✅ الحل الهندسي القياسي (Best Practice)
const user = await prisma.user.findUnique({ select: { id: true, name: true, posts: true } });

التشخيص الهندسي: استخدام include يسحب كل أعمدة الجدول بما فيها الحقول السرية؛ دائماً استخدم select في الـ APIs العامة.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

كيف تنفذ عمليات الكتابة المتداخلة (Nested Writes) مثل إنشاء مستخدم ومقالاته في استدعاء واحد؟

نستخدم خاصية `create` المتداخلة داخل استعلام `prisma.user.create({ data: { name: "Amr", posts: { create: [{ title: "Post 1" }, { title: "Post 2" }] } } })`؛ حيث يقوم بريزما بتغليف كل العمليات تلقائياً داخل معاملة ACID Transaction موحدة.
