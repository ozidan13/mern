كيف حلت Prisma مشكلة الـ N+1 الشهيرة

في الـ ORMs القديمة (زي Sequelize و TypeORM)، لو طلبت 100 مستخدم وعايز مقالاتهم، كان الـ ORM بيعمل استعلام لجلب الـ 100 مستخدم، ثم يلف في حلقة ويعمل 100 استعلام منفصل لجلب مقالات كل مستخدم (101 استعلام تدمر قاعدة البيانات)! محرك Prisma Rust Query Engine يقوم بدمجها تلقائياً في استعلامين اثنين فقط عبر جملة IN (...)، فيحمي الخادم من الانهيار!

7. أخطاء شائعة وفخاخ يقع فيها الجميع · Common Pitfalls

إنشاء كائن new PrismaClient() داخل دوال الـ Routes
// ❌ كارثة: يفتح 1000 اتصال جديد مع كل طلب ويفجر الـ Connection Pool!
app.get('/users', async (req, res) => {
  const prisma = new PrismaClient();
  const users = await prisma.user.findMany();
});
// ✅ سليم: إنشاء مثيل واحد فقط (Singleton Instance) في ملف منفصل
import { prisma } from './lib/prisma.js';
app.get('/users', async (req, res) => {
  const users = await prisma.user.findMany();
});

التشخيص الهندسي: كائن PrismaClient يدير مجمع اتصالات (Connection Pool)، وتكرار إنشائه يستهلك كل مقابس قاعدة البيانات المتاحة.

سؤال مقابلات شهير: إزاي بتتعامل مع أخطاء Prisma الشهيرة زي P2002 و P2025؟

الإجابة الهندسية:
نستخدم فحص error instanceof Prisma.PrismaClientKnownRequestError داخل حارس الأخطاء المركزي:
- إذا كان error.code === 'P2002': يعني (Unique constraint violation - البريد مسجل مسبقاً) فنرجع كود 409 Conflict.
- إذا كان error.code === 'P2025': يعني (Record not found - السجل غير موجود للحذف أو التعديل) فنرجع كود 404 Not Found.
