1. القصة والتشبيه الواقعي · The Core Story

تشبيه بوابات التفتيش الأمني في المطار · Airport Security Gates

تخيل إنك مسافر في مطار دولي.. قبل ما توصل لبوابة الطيارة (Route Handler)، لازم تعدي على سلسلة بوابات تفتيش ورا بعضها (Middleware Pipeline):
- البوابة 1: تفتيش الجوازات والتأشيرة (Auth Middleware).. لو تمام، الضابط يختم ويقولك: "اتفضل على البوابة اللي بعدها" (استدعاء دالة next())!
- البوابة 2: جهاز فحص الحقائب بالأشعة (Body Parser & Validation).. لو شنطتك تمام، تطلع للبوابة اللي بعدها.
- لكن لو في أي بوابة تم اكتشاف مخالفة أو تزوير (throw new Error): الضابط فوراً بيستدعي شرطة المطار (Error Handling Guard) اللي بتاخد المخالف على غرفة التحقيق دون أن يلمس الطيارة إطلاقاً!

المشكلة التي حلتها الـ Middlewares

زمان، كان المطور بيضطر ينسخ كود فحص التوكن وتسجيل السجلات (Logging) وفك الـ JSON في كل مسار من مسارات الـ 50 صفحة في موقعه! مع معمارية الـ Pipeline في Express، بتكتب المنطق في دالة واحدة مركزية، وتطبقها على كل المسارات بكلمة واحدة: app.use(authGuard)!

7. أخطاء شائعة وفخاخ يقع فيها الجميع · Common Pitfalls

استدعاء next() بعد إرسال الرد للعميل
// ❌ خطأ: يرسل الرد ثم يحاول استدعاء الـ Middleware التالي فينهار الخادم!
if (blocked) res.status(403).send('Forbidden');
next(); // ينفذ أيضاً!
// ✅ سليم: استخدام return لإنهاء الدالة فور إرسال الرد
if (blocked) return res.status(403).send('Forbidden');
next();

التشخيص الهندسي: استدعاء next() يوجه الطلب لمعالج آخر سيحاول إرسال رد ثانٍ لنفس الـ Socket المفتوح.

Middleware

Central Error Handler
