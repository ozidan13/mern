The Middleware Conveyor Pipeline & next()

خط سير الوسائط (Middleware Pipeline): معالجة الطلبات بالتسلسل، وظيفة دالة next()، والـ Error Handling Middleware

  • Master execution flow with next(), next('route'), and next(err).
  • Implement custom logging, authentication guard, and rate-limiting middlewares.

1. Core Concept & Mechanics · الفكرة الأساسية

Real-Life Analogy · تشبيه خط التفتيش في المطار (Security Checkpoint)

كل طلب HTTP يدخل السيرفر يشبه مسافراً يدخل المطار ويمر عبر بوابات تفتيش متتالية (Middlewares): 1. البوابة الأولى تسجل وقت الدخول (Logger Middleware).
2. البوابة الثانية تفحص الحقائب وتحلل محتوياتها (express.json Body Parser).
3. البوابة الثالثة تفحص جواز السفر والتأشيرة (Auth Middleware) — إذا كان سليماً يقول الحارس next() ليمر للمرحلة التالية، وإذا كان مزوراً يوقفه فوراً ويرسله لغرفة الطوارئ (Error Handler)!

Definition & Purpose

A Middleware function in Express is a function that has access to the Request object (req), the Response object (res), and the next middleware function in the application's request-response cycle.

دوال الـ Middleware هي حجر الأساس لمعمارية Express. تعمل كسلسلة من المعالجات الوسيطة التي يمكنها فحص الطلب، تعديله، إضافة بيانات له (مثل req.user)، أو إنهاء الطلب فورياً في حالة عدم استيفاء الشروط.

The Three Possible Actions of a Middleware · الخيارات الثلاثة لأي وسيط

1
1. Call next() (المرور للوسيط التالي)

إكمال المعالجة بنجاح وتسليم التحكم للدالة الوسيطة التالية في مكدس السيرفر.

2
2. End the Request (إنهاء الرد فوراً)

إرسال رد للعميل (مثل res.status(401).json(...)) لمنع وصول الطلب للمسارات المحمية.

3
3. Call next(err) (تخطي الجميع والذهاب لمعالج الأخطاء)

تمرير كائن خطأ إلى next(err) يجبر Express على تخطي كل الـ Middlewares العادية والقفز فوراً إلى معالج الأخطاء المركزي.

4. Code Anatomy · تشريح الكود

1: function requireAuth(req, res, next) { 2: const token = req.headers.authorization; 3: if (!token) { 4: return res.status(401).json({ error: 'Unauthorized' }); 5: } 6: req.user = { id: 42, role: 'admin' }; 7: next(); 8: }

السطر 4: إنهاء الطلب بإرجاع 401 فوراً إذا لم يتوفر رمز المصادقة لمنع استدعاء next().

السطر 6: إرفاق بيانات المستخدم المصرح له داخل كائن req.user لتكون متاحة لجميع المسارات اللاحقة.

السطر 7: استدعاء next() للسماح للطلب بالعبور إلى المعالج النهائي.

5. Deep Dive & Complexity Analysis · التحليل والتعقيد

Pipeline Execution Cost
O(M) Middleware Stack

ينفذ Express كل وسيط بالترتيب المحدد خطياً حتى اكتمال السلسلة أو قطعها.

Error Handler Arity
4 Parameters (err, req, res, next)

يتعرف Express على معالج الأخطاء فقط إذا كان عدد معاملاته 4 تماماً (fn.length === 4).

Centralized Error Handling in Express 5.2 
// Centralized Error Handling Middleware (Always defined LAST)
app.use((err, req, res, next) => {
  console.error('[SERVER ERROR]', err.stack);
  const status = err.statusCode || 500;
  res.status(status).json({
    error: {
      message: err.message || 'Internal Server Error',
      code: err.code || 'INTERNAL_ERROR'
    }
  });
});

6. Practice & Common Mistakes · أخطاء شائعة

Forgetting to return when sending a response in Middleware
// ❌ BROKEN (Sends response AND calls next)
if (!isAdmin) res.status(403).send('Forbidden');
next();
// ✅ FIXED (Returns early to prevent next)
if (!isAdmin) return res.status(403).send('Forbidden');
next();

التشخيص: عدم استخدام return يجعل الكود يواصل التنفيذ ويستدعي next()، مما يؤدي إلى تنفيذ المسار التالي ومحاولة إرسال رد ثانٍ ورمي خطأ ERR_HTTP_HEADERS_SENT.

Mini-Glossary · قاموس المصطلحات

next()

8. Production Notes & Interviews · في بيئة العمل والمقابلات

Interview Question: Middleware Ordering Pitfalls

Q: Why must body parsers (express.json) be mounted BEFORE route handlers, and Error handlers AFTER?

الإجابة: لأن Express ينفذ السلسلة بالتسلسل من الأعلى للأسفل: إذا وُضع express.json() بعد المسار، سيصل req.body كـ undefined إلى معالج المسار. وإذا وُضع معالج الأخطاء في البداية، فلن يستقبل أخطاء المسارات المعرفة بعده.
