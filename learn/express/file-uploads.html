Streaming File Uploads: Multer Architecture, Cloud S3/R2 Storage & Malware Validation

رفع ومعالجة الملفات: معمارية Multer، التخزين السحابي على S3/R2 والفحص الأمني للملفات الخبيثة

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم كيفية تحليل طلبات multipart/form-data وتدفق بايتات الملفات باستخدام Multer.
  • تجنب تخزين الملفات على القرص المحلي للخادم ورفعها كـ Streams مباشرة للتخزين السحابي (AWS S3 / Cloudflare R2).
  • فحص الامتدادات الحقيقية للملفات عبر فحص التوقيع السداسي (Magic Bytes) لمنع رفع ملفات الـ Web Shells الخبيثة.
  • تحديد سقوف الأحجام وتوليد أسماء ملفات عشوائية مشفرة لمنع استبدال الملفات.

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

رفع الملفات هو أكثر جزء حساس أمنياً ومعمارياً في أي خادم ويب. المبرمج المبتدئ يقوم برفع الصور وحفظها في مجلد محلي على السيرفر /public/uploads بالاسم الأصلي للملف الذي أرسله المستخدم، ويفحص الامتداد بـ file.originalname.endsWith('.jpg')! هذا الكود يفتح الباب لاختراق الخادم في 30 ثانية: 1. كارثة أمنية: المهاجم يرفع ملف بايلود خبيث اسمه shell.php.jpg أو يغير الـ MIME Type فقط؛ وعندما يفتحه السيرفر، يتم تنفيذ كود خبيث ويسيطر المهاجم على السيرفر بالكامل! 2. كارثة معمارية: عندما تشغل خادمك على Docker أو Heroku أو Kubernetes، فإن القرص الصلب مؤقت (Ephemeral Storage). كلما أعيد تشغيل الـ Pod أو تم توسيع السيرفرات (Auto-scaling)، ستختفي كل ملفات وصور المستخدمين وتضيع للأبد! الحل المعماري هو **التخزين السحابي الموزع (Cloud Object Storage مثل AWS S3 أو Cloudflare R2)** وفحص **التوقيع السداسي الحقيقي للملفات (Magic Bytes)**. في هذا الدرس، هنبني نظام رفع ملفات احترافي فائق الأمان يرفع الملفات كتدفقات مباشرة للسحاب.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

01

تحليل تدفقات Multipart بـ Multer MemoryStorage

استقبال أجزاء الملف في الذاكرة كـ Buffer أو تدفق Stream دون كتابتها على القرص الصلب المحلي للخادم.

02

فحص التوقيع السداسي للملفات (Magic Numbers Validation)

قراءة أول 4 إلى 8 بايتات من الملف للتأكد من هويته الحقيقية (مثلاً FF D8 FF لصور JPEG) بغض النظر عن الامتداد المكتوب.

03

توليد الأسماء العشوائية المشفرة (UUID Filenames)

توليد اسم فريد crypto.randomUUID() + ext لمنع استبدال ملفات المستخدمين الآخرين ومنع هجمات الـ Path Traversal.

04

الرفع السحابي المباشر بـ S3 UploadStream

تمرير الملف مباشرة عبر S3 PutObjectCommand أو multipart upload دون تخزينه محلياً.

05

نمط الروابط الموقعة المسبقة (S3 Presigned URLs)

توليد رابط رفع موقع مؤقت يتيح لمتصفح العميل رفع الملف مباشرة إلى S3 دون المرور بخادمك لتوفير الباندويث والمعالج.

🤔 سؤال تحدي كبار المهندسين:

لماذا يعتبر نمط S3 Presigned URLs أفضل بمراحل معمارياً من رفع الملفات عبر خادم Node.js الخاص بك عند رفع ملفات فيديو ضخمة؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

عند رفع ملف فيديو بحجم 1GB عبر خادم Node.js، فإن الخادم يستهلك 1GB باندويث لاستقبال الملف من العميل + 1GB باندويث أخرى لرفعه إلى S3، بالإضافة لحجز الـ RAM والـ CPU طوال فترة الرفع البطيئة. باستخدام S3 Presigned URLs، يطلب العميل رابطاً موقعاً خفيفاً من الخادم في 5ms، ثم يرفع ملف الـ 1GB مباشرة من المتصفح إلى خوادم S3 في السحاب، موفراً 100% من موارد خادم Node.js وباندويث الشبكة.

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

import multer from "multer";                         // مكتبة معالجة رفع الملفات
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3"; // حزمة AWS S3 SDK v3 الرسمية
const upload = multer({                              // تكوين وسيط الرفع
  storage: multer.memoryStorage(),                   // حفظ الملف في الذاكرة المؤقتة للتدفق المباشر
  limits: { fileSize: 5 * 1024 * 1024 } // 5MB كحد أقصى // تحديد سقف حجم الملف
});                                                  // نهاية تكوين Multer
export const uploadAvatar = upload.single("avatar"); // وسيط رفع ملف فردي

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
// خطأ أمني كارثي: حفظ الملف باسمه الأصلي المرسل من العميل
const storage = multer.diskStorage({
  filename: (req, file, cb) => cb(null, file.originalname) // يتيح استبدال الملفات وثغرات Path Traversal!
});
✅ الحل الهندسي القياسي (Best Practice)
// الحل الهندسي: توليد اسم عشوائي فريد بالكامل
const storage = multer.diskStorage({
  filename: (req, file, cb) => cb(null, crypto.randomUUID() + path.extname(file.originalname))
});

التشخيص الهندسي: الاعتماد على originalname يتيح للمهاجمين استبدال ملفات النظام الحساسة أو كتابة مسارات هروب ../ خبيثة، بينما UUID يضمن الأمان والتفرد.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

سؤال إنترفيو للمهندسين الكبار: كيف تحمي خادمك من ثغرات ImageTragick وثغرات معالجة الصور عندما تستخدم مكتبة مثل Sharp لتغيير أحجام الصور المرفوعة؟

1. فحص الـ Magic Bytes الصارمة للتحقق من أن الملف صورة حقيقية قبل تمريره للمكتبة. 2. تعطيل معالجة صيغ الـ SVG والـ EPS التي قد تحتوي على أكواد XML خبيثة (XML External Entity - XXE) أو نصوص JavaScript قابلة للتنفيذ. 3. تشغيل عمليات معالجة الصور داخل Worker Threads أو معزولة داخل Container فرعي ذي صلاحيات محدودة (Sandboxed Environment). 4. تحديد سقف لأبعاد الصورة القصوى (Max Pixel Dimensions) لمنع هجمات Pixel Flood DoS التي تستهلك كل الـ RAM عند فك ضغط صور بحجم 50,000x50,000 بيكسل.
