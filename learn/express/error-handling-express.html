المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

في إكسبريس 4 القديمة، أي خطأ غير متزامن داخل دالة async كان يتطلب كتابة try/catch يدوياً وتمرير الخطأ لـ next(err)؛ نسيان كتلة واحدة كان يعلق السيرفر في الهواء! إكسبريس 5 أحدثت ثورة بحذف الحاجة لمكتبات مثل express-async-errors؛ حيث تلتقط الوعود المرفوضة (Async Rejections) تلقائياً وتوجهها لوسيط الأخطاء المركزي (Central Error Middleware).

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
الالتقاط التلقائي للـ Async Errors

في إكسبريس 5، أي دالة async ترمي خطأ تُمرره تلقائياً لوسيط الأخطاء دون الحاجة لـ try/catch.

2
وسيط الأخطاء الرباعي

الوسيط المعرف بـ (err, req, res, next) يلتقط كل أخطاء التطبيق في محطة نهائية واحدة.

3
تعقيم الرسائل في الإنتاج

إخفاء الـ Stack Trace وأسماء قواعد البيانات عن المستخدم في بيئة الإنتاج لمنع تسريب المعلومات.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

كيف يتعرف إطار Express على أن دالة معينة هي Error Handling Middleware وليست وسيطاً عادياً؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

عبر فحص عدد معاملات الدالة برمجياً (Function.prototype.length)؛ إذا كانت الدالة تعرف 4 معاملات صراحة (err, req, res, next) يعاملها إكسبريس كوسيط أخطاء حصرياً.

تشريح الكود سطراً بسطر · Code Anatomy

1: app.use((err, req, res, next) => {           // وسيط الأخطاء الرباعي الإلزامي
2:   const code = err.statusCode || 500;           // استخراج كود الحالة
3:   res.status(code).json({ status: "fail", message: err.message }); // إرسال الرد الموحد
4: });                                             // نهاية الوسيط

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
app.use((err, req, res) => { ... }); /* 3 معاملات فقط يعتبره إكسبريس وسيط عادي ويتجاهله عند الأخطاء! */
✅ الحل الهندسي الصحيح (Best Practice)
app.use((err, req, res, next) => { ... }); /* 4 معاملات كاملة تضمن عمل وسيط الأخطاء */

التشخيص الهندسي: حذف معامل next حتى لو لم تستخدمه يقلص طول الدالة لـ 3 معاملات فيفشل إكسبريس في تصنيفها كـ Error Handler.
