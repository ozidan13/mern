السياق والمشكلة الهندسية الواقعية

تشبيه مصلحة السجل المدني واستخراج الشهادات · The Civil Registry Office

تخيل إنك بتتعامل مع مصلحة السجل المدني.. المصلحة منظمة بنظام أسماء الموارد (/citizens أو /passports)، ومبتخترعش أسامي من دماغها!
- لما تقدم طلب تسجيل مواطن جديد: بتبعت استمارة ببياناته (POST /citizens)، والموظف بيختم بـ "تم التسجيل بنجاح" ويديك رقم القومي (201 Created).
- لما تستعلم عن بياناتك: بتطلب بالرقم القومي (GET /citizens/42) فيرد بـ (200 OK).
- لو حبيت تعدل رقم تليفونك بس: بتبعت تعديل جزئي (PATCH /citizens/42).. بينما لو غيرت كل بياناتك بالكامل بتبعت استبدال شامل (PUT /citizens/42).
- ولو قدمت استمارة ناقصة بيانات: الموظف بيرفضها فوراً في وشك بـ (400 Bad Request) قبل ما تدخل على السيستم أصلاً!

2. مصفوفة الـ CRUD القياسية · Step-by-Step Mechanics

POST
1. إنشاء مورد جديد (Create → 201 Created)

المسار: POST /api/v1/articles ← يتحقق من الـ Body وينشئ المعرف الفريد ويرجع الكائن الجديد مع كود 201 Created وترويسة Location.

GET
2. القراءة والاستعلام (Read → 200 OK)

المسار: GET /api/v1/articles/:id ← إذا كان المورد موجوداً يرجع بـ 200 OK، وإذا لم يوجد يرجع 404 Not Found.

DEL
3. الحذف النهائي (Delete → 204 No Content)

المسار: DELETE /api/v1/articles/:id ← يحذف السجل ويرجع كود 204 No Content بدون جسم (Empty Body) لتوفير الباندويث.

5. تشريح مسار إنشاء مورد مع التحقق الشامل · Code Anatomy

1: app.post('/api/v1/users', async (req, res) => { 2: const { email, name } = req.body; 3: if (!email || !email.includes('@')) { 4: return res.status(400).json({ error: 'Valid email is required' }); 5: } 6: const newUser = await db.user.create({ data: { email, name } }); 7: return res.status(201).json(newUser); 8: });

السطر 4: إرجاع كود 400 Bad Request مع رسالة خطأ واضحة عند فشل التحقق.

السطر 7: إرجاع كود 201 Created مع كائن المستخدم الجديد المولد في قاعدة البيانات.

7. أخطاء شائعة وفخاخ يقع فيها الجميع · Common Pitfalls

إرجاع كود 200 OK عند حدوث أخطاء داخل الـ JSON
// ❌ كارثة: تضليل العميل ومكتبات الكاش بـ 200 OK
res.json({ success: false, error: 'User not found' });
// ✅ سليم: استخدام كود HTTP Status 404 القياسي
res.status(404).json({ error: 'User not found' });

التشخيص الهندسي: إرجاع 200 مع أخطاء يمنع المتصفحات ومكتبات الـ Fetch والـ Proxies من اكتشاف الأخطاء ويفسد منطق الـ Retry.

قاموس المصطلحات الأساسية · Mini-Glossary

REST (Representational State Transfer)
نمط معماري قياسي لتصميم واجهات برمجة التطبيقات يعتمد على موارد محددة وأفعال HTTP القياسية.
Idempotency
خاصية في بروتوكول HTTP تضمن أن تنفيذ الطلب عدة مرات متتالية يؤدي لنفس النتيجة على السيرفر كأنه نفذ مرة واحدة.

سؤال مقابلات شهير: إزاي بتعمل Pagination في REST API ضخم بملايين السجلات؟

الإجابة الهندسية:
في الأنظمة الضخمة، نتجنب Offset-based Pagination (OFFSET 1000000) لأنه يجبر قاعدة البيانات على قراءة كل السجلات السابقة في الذاكرة.
وبدلاً من ذلك نستخدم Cursor-based Pagination (Keyset Pagination) عبر تمرير معرف آخر عنصر معروض (WHERE id > last_seen_id ORDER BY id ASC LIMIT 20) مما يجعل الاستعلام ينفذ في زمن فوري O(1) باستخدام الـ Index!
