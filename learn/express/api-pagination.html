API Pagination & Query Optimization: Offset vs Cursor-Based Pagination

تقسيم نتائج الـ API (Pagination): مقارنة الـ Offset والـ Cursor وأداء الفهارس

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم الفرق الجذري في الأداء والتعقيد بين Offset-Based و Cursor-Based Pagination.
  • تطبيق تصفية النتائج والفرز وتحديد الحقول المرجعة ديناميكياً من query parameters.
  • بناء ترويسات وروابط التنقل القياسية (Pagination Metadata & Link Headers).

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

عندما تحتوي قاعدة البيانات على مليون سجل، إرجاع كل البيانات في استدعاء واحد سيسقط الخادم والمتصفح فوراً بخطأ Out of Memory! تقسيم النتائج لصفحات (Pagination) إلزامي. لكن استخدام نمط OFFSET 500000 LIMIT 20 في قواعد البيانات الكبيرة يصبح بطيئاً جداً لأن المحرك يضطر لقراءة نصف مليون سجل وتجاهلهم في الذاكرة قبل إرجاع الـ 20 سجلاً المطلوبة! الحل عالي الكفاءة هو نمط Cursor-Based Pagination.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
التقسيم بالإزاحة (Offset Pagination)

استخدام page و limit في الاستعلامات البسيطة وسهولة التنقل لأي صفحة مباشرة.

2
التقسيم بالمؤشر (Cursor Pagination)

استخدام معرف آخر عنصر تم جلبه (WHERE id > lastId LIMIT 20) لتحقيق سرعة ثابتة O(1) عبر الفهارس.

3
بيانات الصفحات الوصفية (Metadata)

إرجاع معلومات إجمالي الصفحات، الصفحة الحالية، والعدد الكلي للسجلات.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

ما هي المشكلة التي تحدث في Offset Pagination عندما يقوم مستخدم جديد بإضافة سجل في نفس لحظة تصفح الصفحات؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

تحدث ظاهرة تكرار العناصر أو تخطيها (Page Drift / Missing Items)؛ لأن إضافة عنصر جديد في البداية يدفع باقي العناصر خطوة لليمين، فيظهر نفس العنصر مرتين في الصفحة التالية.

تشريح الكود سطراً بسطر · Code Anatomy

1: const page = Math.max(1, parseInt(req.query.page) || 1); // تنظيف رقم الصفحة
2: const limit = Math.min(100, parseInt(req.query.limit) || 20); // تقييد الحد الأقصى لمنع استنزاف السيرفر
3: const skip = (page - 1) * limit;                // حساب الإزاحة
4: const items = await Product.find().skip(skip).limit(limit); // الاستعلام المقسم

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
const limit = req.query.limit; /* لو طلب المستخدم limit=1000000 سيسقط السيرفر! */
✅ الحل الهندسي الصحيح (Best Practice)
const limit = Math.min(100, parseInt(req.query.limit) || 20); /* حماية صارمة بحد أقصى */

التشخيص الهندسي: عدم وضع حد أقصى (Max Limit) يسمح للمخترق بطلب ملايين السجلات في طلب واحد واستنزاف الذاكرة.

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): متى تختار Offset Pagination ومتى تختار Cursor Pagination في تصميم الواجهات؟

نختار `Offset Pagination` في لوحات التحكم والجداول الإدارية التي تتطلب أرقام صفحات واضحة مع إمكانية القفز لصفحة محددة (مثل صفحة 15 مباشرة). ونختار `Cursor Pagination` في التغذيات اللانهائية (Infinite Scroll مثل Twitter و Facebook) وتطبيقات الموبايل لمنع تكرار المنشورات وضمان أعلى سرعة استجابة.
