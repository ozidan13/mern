Schema Validation & Sanitization with Zod in Express APIs

التحقق الصارم وتطهير البيانات بمكتبة Zod في خوادم إكسبريس

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • بناء مخططات Zod Schemas للتحقق من req.body و req.query و req.params.
  • بناء وسيط تحقق عام (validateRequest Middleware) يعترض البيانات الخاطئة مبكراً.
  • تطهير البيانات وحذف الحقول الإضافية غير المصرح بها تلقائياً (Strip Unknown Keys).

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

قاعدة الأمان الذهبية في هندسة البرمجيات: "لا تثق أبداً في مدخلات العميل!" (Never Trust User Input). استقبال بيانات غير مفحوصة في req.body أو req.query يفتح الباب لحقن الشيفرات، انهيار السيرفر بسبب أنواع خاطئة، وتخزين بيانات مشوهة في قاعدة البيانات. مكتبة Zod توفر أماناً نوعياً متكاملاً وقت التشغيل (Runtime Validation) ووقت التجميع (TypeScript Type-Inference).

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
تعريف المخطط الصارم (Schema Definition)

تحديد الحقول المطلوبة وأنواعها وقواعدها (البريد، طول كلمة السر، الأرقام الموجبة).

2
الفحص الآمن (safeParse)

استخدام safeParse لإرجاع كائن { success, data, error } دون رمي استثناءات غير مسيطر عليها.

3
استبدال المدخلات بالبيانات المعقمة

إسناد result.data المفحوصة والمطهرة إلى req.body قبل وصولها لدالة المسار.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

ما هي ميزة schema.strip() الافتراضية في Zod عند استلام حقول إضافية غير معرفة؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

تقوم Zod تلقائياً بحذف وتجريد أي حقول إضافية أرسلها العميل لم تكن معرفة في الـ Schema، مما يحمي من ثغرات تعديل الخصائص الجماعي (Mass Assignment Vulnerability).

تشريح الكود سطراً بسطر · Code Anatomy

1: export const validate = (schema) => (req, res, next) => { // وسيط تحقق عام
2:   const result = schema.safeParse(req.body);    // فحص آمن للبيانات
3:   if (!result.success) return res.status(400).json({ errors: result.error.format() }); // رد فوري بالأخطاء
4:   req.body = result.data; next();               // تمرير البيانات المطهرة
5: };                                              // نهاية الوسيط

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
const user = await User.create(req.body); /* ثغرة Mass Assignment تتيح للمستخدم إرسال role: "admin"! */
✅ الحل الهندسي الصحيح (Best Practice)
const cleanData = userSchema.parse(req.body); const user = await User.create(cleanData);

التشخيص الهندسي: تمرير req.body مباشرة لقاعدة البيانات دون فحص يتيح للمخترقين حقن حقول حساسة مثل الصلاحيات والأرصدة.

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): كيف تستخرج أنواع TypeScript تلقائياً من مخطط Zod Schema (Type Inference)؟
