Role-Based Access Control (RBAC), Permissions & Auth Guards

التحكم بالوصول القائم على الأدوار (RBAC) وحراس الصلاحيات

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم الفرق الجذري بين Authentication (401 Unauthorized) و Authorization (403 Forbidden).
  • بناء وسيط حماية الأدوار restrictTo("admin", "lead-guide").
  • تطبيق مبدأ التحقق من الملكية (Resource Ownership Checks).

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

التوثيق (Authentication) يجيب على سؤال: "من أنت؟"، بينما التفويض (Authorization) يجيب على سؤال: "ما الذي يحق لك فعله؟". السماح لمستخدم عادي بحذف مقال أو تعديل حساب مستخدم آخر بسبب غياب حراس الصلاحيات يُعد ثغرة خطيرة من نوع IDOR (Insecure Direct Object Reference). في هذا الدرس سنبني نظام RBAC متين يعتمد على وسائط الحماية (Role Guards).

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

1

التحقق من الهوية أولاً (Auth Guard)

فك تشفير الرمز والتأكد من صحته وحفظ بيانات المستخدم في req.user.

2

فحص الدور والصلاحية (Role Guard)

مطابقة دور المستخدم req.user.role مع قائمة الأدوار المسموح لها بدخول المسار.

3

فحص ملكية المورد (Ownership Check)

التأكد من أن المستخدم يقوم بتعديل موارده الخاصة فقط ما لم يكن يمتلك صلاحية Admin.

🤔 سؤال تحدي كبار المهندسين:

ما هو كود حالة HTTP الصحيح عندما يحاول مستخدم مسجل دخول بالفعل الوصول لمسار لا يملك صلاحيته؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

كود الحالة الصحيح هو 403 Forbidden (ممنوع الوصول)؛ استخدام 401 Unauthorized هنا خاطئ لأن 401 تعني أن المستخدم غير معروف ويحتاج لتسجيل الدخول أولاً.

تشريح الكود المعماري سطراً بسطر · Annotated Code Anatomy

1: export const restrictTo = (...roles) => (req, res, next) => { // مصنع وسائط الصلاحيات
2:   if (!roles.includes(req.user.role)) {           // فحص دور المستخدم
3:     return res.status(403).json({ message: "You do not have permission" }); // رفض الوصول 403
4:   }                                               // نهاية الفحص
5:   next();                                         // السماح بالمرور
6: };                                                // نهاية الوسيط

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
app.delete("/users/:id", deleteUser); /* ثغرة IDOR: أي مستخدم يقدر يحذف أي حساب! */
✅ الحل الهندسي القياسي (Best Practice)
app.delete("/users/:id", protect, restrictTo("admin"), deleteUser); /* محمي بالصلاحيات */

التشخيص الهندسي: عدم فحص الصلاحيات يتيح للمستخدمين استدعاء مسارات الحذف والتعديل بتغيير الـ ID في الـ URL فقط.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

ما هو الفرق بين RBAC (Role-Based) و ABAC (Attribute-Based Access Control)؟

في RBAC تعتمد الصلاحيات على المسمى الوظيفي للمستخدم (مثل Admin أو Member). بينما في ABAC تعتمد الصلاحيات على سمات ديناميكية متعددة مثل (هل المستخدم هو صاحب المستند؟ هل الوقت أثناء ساعات العمل؟ هل عنوان الـ IP يقع داخل الشركة؟) مما يوفر دقة متناهية (Fine-Grained Authorization).
