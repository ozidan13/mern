رؤية الواقع العملي · Real-World Context & Mental Model

التعامل مع ملفات السيرفر بـ Sync APIs مثل fs.readFileSync هي جريمة هندسية في خوادم الإنتاج؛ لأنها تجمد خيط المعالجة الرئيسي (Main Thread) وتمنع كل المستخدمين الآخرين من تصفح الموقع حتى تنتهي قراءة القرص! استخدام node:fs/promises يتيح قراءة وكتابة وتعديل الملفات بسرعة فائقة عبر خيوط libuv الخلفية.

🤔 سؤال تحدي المهندسين:

ما هو الفرق بين path.join() و path.resolve() في Node.js؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

الدالة path.join تدمج أجزاء المسارات معاً وتطبع المسار الناتج، بينما path.resolve تعالج المسارات من اليمين لليسار حتى تبني مساراً مطلقاً (Absolute Path) معتمداً على مجلد العمل الحالي (CWD).

2: import path from "node:path";                   // مكتبة المسارات
3: const content = await fs.readFile(safePath, "utf-8"); // قراءة غير محجوبة مع تشفير النصوص

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
fs.readFileSync("huge-file.json"); /* يجمد السيرفر بالكامل أثناء القراءة! */
✅ الحل الهندسي الصحيح (Best Practice)
await fs.readFile("huge-file.json", "utf-8"); /* تشغيل غير محجوب في خيوط libuv */

التشخيص الهندسي: دوال Sync تجمد خيط التنفيذ الوحيد وتمنع معالجة أي طلبات مستخدمين أخرى حتى ينتهي القرص.
