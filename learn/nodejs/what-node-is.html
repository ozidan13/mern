المشكلة التي حلتها Node.js في عالم الخوادم

في السيرفرات التقليدية القديمة (زي خوادم Apache مع PHP)، كان كل ما يجيلك مستخدم جديد، السيرفر يضطر ينشئ Thread منفصل في نظام التشغيل ويحجز له 2MB رام. لو جالك 10 آلاف مستخدم في نفس اللحظة، السيرفر محتاج 20GB رام لمجرد إبقاء الخيوط مفتوحة، وكان بينهار تحت وطأة ما يعرف بمشكلة C10K Problem! جاء ريان دال (Ryan Dahl) في 2009 وابتكر Node.js: خيط واحد خفيف جداً يخدم الجميع عبر الـ Event-Driven Non-Blocking Architecture، فوفر 90% من استهلاك السيرفرات!

7. أخطاء شائعة وفخاخ يقع فيها الجميع · Common Pitfalls

استخدام الدوال المتزامنة (Sync APIs) داخل مسارات السيرفر
// ❌ كارثة: يجمد السيرفر بالكامل ويمنع أي مستخدم آخر من الدخول!
app.get('/data', (req, res) => {
  const file = fs.readFileSync('big.json');
  res.send(file);
});
// ✅ سليم: تفويض القراءة للـ libuv واستخدام التدفق غير المتزامن
app.get('/data', async (req, res) => {
  const file = await fs.readFile('big.json');
  res.send(file);
});

التشخيص الهندسي: دوال `*Sync` تجبر محرك V8 على التوقف عن العمل حتى ينتهي القرص الصلب من القراءة، فيتجمد كل مستخدمي الموقع.

قاموس المصطلحات الأساسية · Mini-Glossary

libuv
مكتبة مفتوحة المصدر مكتوبة بلغة C++ مسؤولة عن إدارة الـ Event Loop والـ Thread Pool والتفاعل غير المتزامن مع أنظمة التشغيل في Node.js.
Non-Blocking I/O
نموذج تشغيل يسمح للبرنامج ببدء عملية قراءة أو كتابة طويلة ثم المتابعة فوراً لتنفيذ مهام أخرى دون الانتظار لانتهاء العملية الأولى.

الإجابة الهندسية:
بما أن نود تعمل بخيط واحد لكل Process، فإننا نستغل كامل أنوية المعالج عبر:
1. Cluster Module المدمج في Node.js لإنشاء نسخ فرعية (Worker Processes) تتقاسم نفس المنفذ.
2. في الإنتاج، نستخدم مديري العمليات مثل PM2 في وضع الـ Cluster (`pm2 start app.js -i max`).
3. استخدام حاويات Docker و Kubernetes لنشر حاويات متعددة مع Load Balancer أمامي (Nginx أو AWS ALB).
