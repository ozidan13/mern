1. Core Concept & Mechanics · الفكرة الأساسية

Real-Life Analogy · تشبيه القطار الدائري والمحطات الست

حلقة الأحداث في Node.js تشبه قطاراً دائرياً مستمراً يمر بـ 6 محطات محددة: 1. محطة المواعيد المحددة (Timers).
2. محطة الأخطاء المعلقة (Pending I/O).
3. محطة الصيانة الداخلية (Idle/Prepare).
4. محطة استلام البضائع الجديدة واستقبال اتصالات الشبكة (Poll).
5. محطة التنفيذ الفوري (Check / setImmediate).
6. محطة الإغلاق وتنظيف الموارد (Close Callbacks).
وقبل أن يتحرك القطار من أي محطة للمحطة التالية، يتوقف لحظياً لخدمة ركاب الدرجة الأولى الممتازة (process.nextTick)!

Definition & Purpose

The Event Loop is what allows Node.js to perform non-blocking I/O operations despite JavaScript being single-threaded. It constantly iterates through six distinct queues managed by libuv, processing callbacks and coordinating asynchronous operations.

حلقة الأحداث (Event Loop) هي المحرك الأساسي لبيئة Node.js. تعمل كحلقة تكرار لانهائية تديرها مكتبة libuv، وتمر بانتظام عبر 6 مراحل متتالية لمعالجة الـ Callbacks وتنفيذ الشيفرات البرمجية فور جاهزيتها.

The 6 Chronological Phases · المراحل الست لحلقة الأحداث

1
1. Timers Phase

تنفيذ الـ Callbacks المجدولة عبر setTimeout() و setInterval() التي انتهت مدتها الزمنية.

2
2. Pending Callbacks

تنفيذ استدعاءات أخطاء النظام المؤجلة (مثل أخطاء مقابس TCP من نوع ECONNREFUSED).

3
3. Idle / Prepare

مرحلة داخلية خاصة بنظام libuv فقط لتجهيز ومزامنة العمليات الداخلية.

4
4. Poll Phase (المحطة المركزية)

استرداد أحداث الإدخال والإخراج الجديدة (قراءة الملفات، طلبات HTTP الواردة)، والانتظار في حالة عدم وجود مهام.

5
5. Check Phase (setImmediate)

تنفيذ الدوال المجدولة صراحة عبر setImmediate() فور انتهاء مرحلة الـ Poll مباشرة.

6
6. Close Callbacks

تنفيذ استدعاءات إغلاق المقابس والموارد المنتهية (مثل socket.on('close')).

Which executes first: process.nextTick() or Promise.then()?

أيهما يسبق الآخر في التنفيذ: process.nextTick أم Promise.then؟

process.nextTick() ينفذ أولاً دائماً! يمتلك طابور nextTick أولوية مطلقة يتم تفريغها بالكامل حتى قبل طابور وعود جافاسكربت (Promise Microtasks).

4. Code Anatomy · تشريح الكود

1: setTimeout(() => console.log('Timer'), 0); 2: setImmediate(() => console.log('Immediate')); 3: process.nextTick(() => console.log('NextTick')); 4: Promise.resolve().then(() => console.log('Promise'));

السطر 3: process.nextTick ينفذ أولاً فور انتهاء الكود المتزامن الحالي.

السطر 4: Promise.then ينفذ ثانياً كجزء من الـ Microtask Queue.

5. Deep Dive & Complexity Analysis · التحليل والتعقيد

O(1) Queue Pointer

الانتقال بين مراحل الـ Event Loop يتم بزمن ثابت O(1) عبر مؤشرات طوابير libuv.

nextTick Starvation Risk
I/O Starvation

الاستدعاء التكراري المتواصل لـ process.nextTick يمنع الـ Event Loop من الانتقال للمرحلة التالية تماماً.

setTimeout vs setImmediate in I/O Callbacks

داخل أي معالج إدخال وإخراج (مثل fs.readFile)، دالة setImmediate تنفذ دائماً قبل setTimeout! السبب: مرحلة قراءة الملف تقع في الـ Poll Phase، والمرحلة التالية لها مباشرة في الدورة هي الـ Check Phase (مكان setImmediate).

6. Practice & Common Mistakes · أخطاء شائعة

Recursive process.nextTick Starvation
// ❌ STARVATION (Event loop never advances)
function loop() {
  process.nextTick(loop);
}
// ✅ SAFE (Allows other I/O phases to run)
function loop() {
  setImmediate(loop);
}

التشخيص: لأن nextTick يفرغ طابوره قبل التقدم لأي مرحلة أخرى، التكرار اللانهائي يجوع عمليات الشبكة والملفات تماماً.
