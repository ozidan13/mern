1. القصة والتشبيه الواقعي · The Core Story

تشبيه قطار المترو الدائري والممر السريع VIP · The 6-Station Metro Loop

تخيل إن حلقة الـ Event Loop في نود جي إس عبارة عن قطار مترو دائري بيتحرك بين 6 محطات محددة ورا بعضهم ومبيقفش أبداً:
1. محطة المؤقتات (Timers): بيفحص التايمرز اللي وقتها جه (setTimeout / setInterval).
2. محطة الإدخال والإخراج المعلقة (Pending I/O): بيعالج أخطاء الشبكة والـ Sockets القديمة.
3. محطة الاستعداد الداخلي (Idle, Prepare): صيانة داخلية لمحرك libuv.
4. محطة الفحص الرئيسية (Poll Phase): المحطة الأهم اللي بيستقبل فيها طلبات الـ HTTP الجديدة وقراءة الملفات!
5. محطة التنفيذ الفوري (Check Phase): مخصصة حصرياً لتشغيل دوال setImmediate().
6. محطة الإغلاق (Close Callbacks): تنظيف الـ Sockets المغلقة مثل socket.on('close').
أما دالة process.nextTick(): فهي زي ممر الطوارئ VIP السريع: بتنفذ فوراً بين كل محطة والتانية قبل ما القطار يدخل المحطة التالية!

المشكلة التي يقع فيها المطورون مع التوقيت

كثير من المطورين يعتقدون أن setImmediate تعني التنفيذ قبل process.nextTick بسبب الاسم، لكن الحقيقة المعمارية هي العكس تماماً! process.nextTick ليست جزءاً من الـ Event Loop أصلاً، بل هي Microtask يفرغه محرك Node.js مباشرة بعد انتهاء الكود الحالي، بينما setImmediate تنفذ في المحطة رقم 5 (Check Phase).

7. أخطاء شائعة وفخاخ يقع فيها الجميع · Common Pitfalls

الاعتقاد بأن setTimeout(0) تعني التنفيذ الفوري في 0 ملي ثانية
// ❌ خطأ: تايمر 0ms في Node.js يتحول أوتوماتيكياً إلى 1ms كحد أدنى لنظام التشغيل
setTimeout(fn, 0);
// ✅ إذا كنت تريد التنفيذ الفوري بعد الـ Poll مباشرة استخدم setImmediate
setImmediate(fn);

التشخيص الهندسي: محرك libuv يفرض حداً أدنى لـ `setTimeout` قدره 1ms بسبب قيود ساعات أنظمة التشغيل (OS Clock Resolution).

قاموس المصطلحات الأساسية · Mini-Glossary

Poll Phase
المرحلة الأساسية في Event Loop التي تحسب كم من الوقت يجب الانتظار لحزم الشبكة والـ I/O وتعالج الطلبات الواردة.
setImmediate
دالة خاصة بـ Node.js مصممة لتشغيل كود في مرحلة الـ Check Phase فور انتهاء مرحلة الـ Poll مباشرة.
