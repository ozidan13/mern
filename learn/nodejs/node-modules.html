Module Systems: CommonJS vs ECMAScript Modules (ESM) in Node.js 24

أنظمة الوحدات في Node.js 24: مقارنة CommonJS و ES Modules

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم خوارزمية البحث عن الملفات (Module Resolution Algorithm) في Node.js.
  • التحويل النظيف من CommonJS إلى ES Modules باستخدام "type": "module".
  • إتقان استخدام Top-Level Await وحل بدائل __dirname عبر import.meta.url.

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

في بيئة Node.js الحديثة، فهم كيفية تحميل الوحدات (Module Loading Algorithm) هو الفارق بين خادم سريع التحميل وخادم ينهار بأخطاء مثل ERR_REQUIRE_ESM. نظام CommonJS يعتمد على دوال require المتزامنة التي تحجب الـ Event Loop أثناء قراءة القرص، بينما نظام ESM يعتمد على التحليل الثابت والتحميل غير المتزامن الذي يسمح بالـ Top-Level Await والـ Tree-Shaking.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
التحميل وحفظ الكاش (Module Caching)

عند استدعاء require أو import لأول مرة، يقوم Node.js بتنفيذ الملف وحفظ النتيجة في require.cache لتجنب إعادة التنفيذ.

2
الـ Top-Level Await في ESM

إمكانية استخدام await مباشرة في رأس الملف دون الحاجة لتغليفها داخل دالة async فورية (IIFE).

3
الحزم المشتركة (Dual Packages)

تكوين حقل "exports" في package.json لدعم الاستيراد بـ CJS و ESM معاً.

🤔 سؤال تحدي المهندسين:

ماذا يحدث إذا حاولت استخدام Top-Level Await داخل ملف CommonJS؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

سيلقي المحرك خطأ فورياً من نوع SyntaxError: await is only valid in async functions and the top level bodies of modules.

تشريح الكود سطراً بسطر · Code Anatomy

1: // package.json                                 // تعريف نوع المشروع
2: { "type": "module" }                            // تفعيل نظام ESM القياسي لجميع ملفات .js
3: import { db } from "./database.js";             // استيراد معياري
4: await db.connect(); // Top-Level Await          // اتصال فوري قبل تصدير السيرفر

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
const db = require("./db.mjs"); /* خطأ: CJS لا يستطيع استيراد ملف ESM متزامن */
✅ الحل الهندسي الصحيح (Best Practice)
import { db } from "./db.js"; /* استيراد متوافق بنظام ESM */

التشخيص الهندسي: محاولة استدعاء ملف ESM بـ require تفشل لأن ESM غير متزامن ويجب استيراده بـ import أو dynamic import().

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): كيف تعالج التبعيات الدائرية (Circular Dependencies) في Node.js بين CJS و ESM؟

في CommonJS، إذا كان هناك ملفان يستدعيان بعضهما، يُرجع أحدهما كائن `exports` غير مكتمل وقت التقييم. أما في ESM، فالتحليل الثابت يربط المتغيرات بالمرجع (Live Bindings)، لكن إذا تم الوصول لمتغير في منطقة الـ TDZ سيلقي ReferenceError. الحل الهندسي هو إعادة هيكلة الكود وفصل التبعية المشتركة في ملف ثالث.
