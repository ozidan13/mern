Multiprocessing in Node.js: spawn, fork, exec & Worker Threads

تعدد المعالجات في Node.js: العمليات الفرعية وخيوط المعالجة (Worker Threads)

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • التمييز الصارم بين spawn (للتدفق المباشر) و exec (للبافر المؤقت) و fork (لعمليات Node المستقلة).
  • استخدام Worker Threads لمعالجة المهام الحسابية الثقيلة دون حجب الـ Event Loop.
  • تبادل الرسائل الآمن (MessageChannel & postMessage) بين الخيط الرئيسي وخيوط الـ Workers.

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

الـ Single Thread في Node.js ممتاز للعمليات المعتمدة على الشبكة والقرص (I/O-Bound)، لكن إذا طلب مستخدم معالجة صورة ضخمة أو تشفير فيديو أو حساب معادلات رياضية معقدة (CPU-Bound)، فإن الخيط الرئيسي سيتجمد تماماً ويتوقف الخادم عن الرد على أي مستخدم آخر! لحل هذه المعضلة، نوفر وحدتين: node:child_process لتشغيل أوامر النظام وعمليات Node فرعية، و node:worker_threads لتشغيل خيوط حقيقية تشترك في الذاكرة عبر SharedArrayBuffer.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
التدفق المباشر بـ spawn

تشغيل أوامر النظام واستقبال مخرجاتها كـ Stream مباشر للذاكرة دون حدوث Buffer Overflow.

2
العمليات المستقلة بـ fork

إنشاء عملية Node.js جديدة بالكامل بقناة اتصال IPC (Inter-Process Communication).

3
خيوط المعالجة Worker Threads

تشغيل عدة محركات V8 داخل نفس العملية ومشاركة الذاكرة لنقل البيانات الضخمة بـ Zero-Copy.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

لماذا يعتبر child_process.spawn أكثر أماناً وكفاءة بمراحل من child_process.exec للملفات الكبيرة؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لأن exec تقوم بتخزين كل المخرجات في الذاكرة المؤقتة (Buffer بحد أقصى 1MB افتراضياً) وإذا تجاوزتها المخرجات ينهار التطبيق بخطأ maxBuffer exceeded، بينما spawn تتدفق المخرجات كـ Streams دون أي حد لحجم البيانات.

تشريح الكود سطراً بسطر · Code Anatomy

1: import { Worker } from "node:worker_threads";   // استيراد خيوط المعالجة
2: const worker = new Worker("./heavy-calc.js");   // إطلاق الخيط في ملف منفصل
3: worker.postMessage({ numbers: [1, 2, 3] });     // إرسال البيانات للخيط
4: worker.on("message", (result) => updateUI(result)); // استقبال النتيجة بدون تجميد

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
exec(`convert ${userInput}`); /* ثغرة كارثية للحقن Command Injection! */
✅ الحل الهندسي الصحيح (Best Practice)
spawn("convert", [sanitizedInput]); /* آمن تماماً ولا يمرر الأوامر للـ Shell */

التشخيص الهندسي: دالة exec تمرر الأوامر لمفسر النظام (Shell) مما يسمح للمخترق بحقن أوامر خبيثة عبر الفاصلة المنقوطة (;).

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): ما هو الفرق الجوهري بين Cluster Module و Worker Threads في Node.js؟

الـ `Cluster Module` ينشئ عمليات مستقلة تماماً (Multiple Processes) كل منها يمتلك ذاكرة ومحرك V8 و Event Loop منفصل لاستغلال كل أنوية المعالج في توزيع طلبات الشبكة. أما `Worker Threads` فتعمل داخل نفس العملية وتشترك في الذاكرة وهي مخصصة للمهام الحسابية الثقيلة (CPU-bound tasks).
