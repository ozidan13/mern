Worker Threads (worker_threads): Multi-Threading, SharedArrayBuffer & Atomics

خيوط العمل المتعددة (Worker Threads): البرمجة متوازية الخيوط، الذاكرة المشتركة وعمليات Atomics

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • تنفيذ المهام الحسابية الشاقة (CPU-bound tasks) على خيوط عمل حقيقية في الخلفية دون حظر الـ Event Loop.
  • إنشاء قنوات التراسل (MessageChannel & MessagePort) وتبادل البيانات بين الخيوط.
  • مشاركة الذاكرة الصفرية (Zero-Copy Shared Memory) باستخدام SharedArrayBuffer.
  • تجنب سباق البيانات (Race Conditions) باستخدام عمليات Atomics الذرية (Atomics.add, Atomics.wait).

المشكلة الهندسية والسياق الواقعي · The Architectural Problem

رؤية الواقع العملي والنموذج الذهني · Real-World Context & Mental Model

خادم Node.js يشتهر بأنه فائق السرعة في مهام الـ I/O-bound (مثل قراءة قواعد البيانات واستقبال طلبات الـ HTTP)، لكنه كان يعاني تاريخياً في المهام الحسابية (CPU-intensive tasks). لو كتبت دالة تحسب الأرقام الأولية (Prime Numbers) أو خوارزمية ذكاء اصطناعي تستغرق 5 ثوانٍ على الخيط الرئيسي، فإن خادمك سيتوقف بالكامل عن خدمة أي مستخدم طوال الـ 5 ثوانٍ! وحدة **worker_threads** جلبت "البرمجة الحقيقية متوازية الخيوط" (True Multi-Threading) إلى Node.js! تتيح لك تشغيل خيوط عمل متعددة داخل نفس عملية الخادم، كل خيط يملك V8 Engine مستقل وخاص به، ويعمل على نواة معالج مختلفة بالتوازي التام. والأروع من ذلك هو إمكانية مشاركة الذاكرة بين الخيوط بسرعة الضوء دون أي نسخ للبيانات (Zero-Copy) باستخدام **SharedArrayBuffer** وتأمين العمليات الذرية بـ **Atomics**. في هذا الدرس، هنبني Thread Pool متكامل لتوزيع المهام الحسابية، وهنتعلم إزاي ننقل البيانات الضخمة بين الخيوط في أجزاء من الميلي ثانية.

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution Pipeline

01

إنشاء خيط العمل المستقل بـ new Worker()

تحميل ملف جافاسكريبت في خيط عمل فرعي منفصل يمتلك V8 Isolate خاصاً به وتمرير البيانات المبدئية عبر workerData.

02

التراسل بين الخيوط عبر parentPort

إرسال واستقبال الرسائل بـ parentPort.postMessage() والاستماع للأحداث بـ worker.on("message").

03

مشاركة الذاكرة الصفرية بـ SharedArrayBuffer

حجز كتلة ذاكرة خام في الـ RAM مشتركة بين الخيط الرئيسي وخيوط العمل لتعديل البيانات دون أي استهلاك للنقل.

04

العمليات الذرية المتزامنة بـ Atomics API

استخدام Atomics.add() و Atomics.load() و Atomics.wait() لضمان سلامة العمليات المتزامنة وتجنب سباق الذاكرة (Race Conditions).

05

بناء مجمع الخيوط وإعادة الاستخدام (Worker Thread Pool)

الحفاظ على عدد ثابت من خيوط العمل (مثل 4 أو 8 خيوط) وإعادة استخدامها لتجنب تكلفة إنشاء خيوط جديدة مع كل طلب.

import { Worker, isMainThread, parentPort, workerData } from "node:worker_threads"; // استيراد وحدة خيوط العمل
if (isMainThread) {                                  // كود الخيط الرئيسي
  const worker = new Worker(new URL(import.meta.url), { // إنشاء خيط العمل
    workerData: { matrixSize: 1000 }                 // تمرير البيانات الابتدائية للخيط
  });                                                // نهاية إنشاء الخيط
  worker.on("message", (result) => console.log("Result:", result)); // استقبال النتيجة المحسوبة
} else {                                             // كود خيط العمل الفرعي
  const result = heavyCpuCalculation(workerData.matrixSize); // تنفيذ الحسابات الثقيلة في الخلفية
  parentPort.postMessage(result); // إرسال النتيجة للأصل // إرسال الرد للخيط الرئيسي
}                                                    // نهاية التحقق

معرض الأخطاء الشائعة والحلول الهندسية · Production Mistakes Gallery

❌ الكود المسبب للأعطال (Anti-Pattern)
// خطأ كارثي: تنفيذ عمليات تشفير أو حسابات مصفوفات ثقيلة على الخيط الرئيسي
app.post("/resize-image", (req, res) => {
  const thumbnail = heavyImageResize(req.body.image); // يجمد الخادم لمدة ثانية كاملة عن باقي المستخدمين!
  res.send(thumbnail);
});
✅ الحل الهندسي القياسي (Best Practice)
// الحل الهندسي: تفويض المهمة لـ Worker Thread Pool
app.post("/resize-image", async (req, res) => {
  const thumbnail = await workerPool.exec("resizeImage", req.body.image); // تنفيذ متوازي بدون حظر الـ Event Loop
  res.send(thumbnail);
});

التشخيص الهندسي: المهام الحسابية الثقيلة تحظر الـ Event Loop وتشل قدرة خادم Node.js على خدمة اتصالات المستخدمين، بينما Worker Threads توزع الحمل على أنوية المعالج المتعددة.

💼 سؤال إنترفيو للمهندسين الكبار (Senior Interview Question)

سؤال إنترفيو للمهندسين الكبار: كيف تنفذ نمط MessagePort و Transferable Objects لنقل ملكية Buffer بحجم 500MB بين الخيوط بدون استهلاك بايت واحد إضافي من الـ RAM؟

نستخدم خاصية Transferable Objects في postMessage: نستدعي parentPort.postMessage({ buffer }, [buffer.buffer]). تمرير الـ ArrayBuffer كمعامل ثانٍ في مصفوفة النقل يخبر محرك V8 بنقل ملكية مؤشر الذاكرة (Memory Pointer Transfer) فوراً إلى الخيط المستقبل وتفريغه من الخيط المرسل (Detached Buffer) في زمن 0ms وبدون نسخ أي بايت في الذاكرة، محققاً أقصى كفاءة أداء ممكنة في معالجة الملفات الضخمة.
