5. تشريح نمط نقل الملفات الآمن عبر stream.pipeline · Code Anatomy

1: import { pipeline } from 'node:stream/promises'; 2: import fs from 'node:fs'; 3: import zlib from 'node:zlib'; 4: 5: async function compressFile(source, destination) { 6: await pipeline( 7: fs.createReadStream(source), 8: zlib.createGzip(), 9: fs.createWriteStream(destination) 10: ); 11: }

السطر 6: دالة pipeline الحديثة تتفوق على .pipe() القديمة لأنها تغلق جميع التيارات وتنظف الموارد تلقائياً في حالة حدوث أي خطأ في منتصف النقل.

السطر 8: تيار التحويل zlib.createGzip() يضغط البيانات أثناء تدفقها دون تخزين الملف كاملاً.

6. كواليس هندسية وتحليل الأداء · Deep Dive

كفاءة الذاكرة الثابتة
O(1) Memory Usage

استهلاك الذاكرة يظل ثابتاً بحجم الـ highWaterMark (64KB) بغض النظر عما إذا كان حجم الملف 1MB أو 100GB.

أمان الـ Buffer القديم
Buffer.allocUnsafe Danger

استخدام Buffer.allocUnsafe يحجز ذاكرة قديمة دون تصفيرها بالأصفار، مما قد يسرب كلمات مرور أو بيانات حساسة لعملاء آخرين!

7. أخطاء شائعة وفخاخ يقع فيها الجميع · Common Pitfalls

استخدام .pipe() القديم دون معالجة أخطاء الـ Dest
// ❌ كارثة: لو انقطع اتصال العميل، تيار القراءة يفضل شغال ويسرب File Descriptors!
src.pipe(res);
// ✅ سليم: pipeline تغلق كل التيارات تلقائياً عند أي خطأ
await pipeline(src, res);

التشخيص الهندسي: دالة .pipe() القديمة لا تعيد توجيه أخطاء التدمير (Destruction Errors)، مما يترك مسارات الملفات معلقة (EMFILE error).

قاموس المصطلحات الأساسية · Mini-Glossary

Backpressure
آلية ضبط تدفق البيانات التي تخبر تيار القراءة بالتوقف المؤقت عندما يكون تيار الكتابة مشغولاً أو بطيئاً لحماية الذاكرة من التراكم.
highWaterMark
الحد الأقصى لعدد البايتات التي يمكن تخزينها في Buffer التيار الداخلي قبل تفعيل إشارة التوقف المؤقت (افتراضياً 64KB للـ fs و 16KB للـ Sockets).
