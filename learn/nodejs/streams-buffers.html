Streams, Buffers & Backpressure Handling

معالجة البيانات الضخمة مع الـ Streams والـ Buffers، وإدارة الضغط العكسي (Backpressure) باستخدام pipeline

Learning Objectives · أهداف الدرس

  • Master the four Stream types: Readable, Writable, Duplex, and Transform.

1. Core Concept & Mechanics · الفكرة الأساسية

Real-Life Analogy · تشبيه مشاهدة فيلم عبر البث (Streaming)

إذا أردت مشاهدة فيلم بحجم 10GB، فلن تنتظر تحميل الـ 10GB بالكامل إلى ذاكرة جهازك قبل أن تبدأ اللقطة الأولى! (هذا ما تفعله fs.readFile العادية، مما يفجر ذاكرة الـ RAM). بدلاً من ذلك، تشاهد الفيلم عبر البث المباشر (Stream): يستقبل مشغلك قطعة صغيرة (Chunk / Buffer) بحجم 64KB، يعرضها على الشاشة، ثم يستقبل القطعة التالية ويفرغ القديمة، مما يتيح معالجة ملفات بحجم 100GB باستخدام 20MB فقط من الذاكرة!

Definition & Purpose

Streams are collections of data that might not be available all at once and don't have to fit in memory. In Node.js, streams provide an event-driven interface for chunk-by-chunk data processing (such as disk I/O, HTTP requests, and compression).

الـ Streams هي الوسيلة المثلى في Node.js لمعالجة كميات البيانات الضخمة التي تتجاوز سعة الذاكرة العشوائية (RAM). تتيح قراءة وكتابة وتعديل البيانات على هيئة قطع صغيرة متتالية (Chunks)، مما يوفر كفاءة زمنية واستقراراً لا يضاهى.

2
2. Writable Stream (تدفق للكتابة)

3. Transform Stream (تدفق للتحويل والمعالجة)

تدفق مزدوج يستقبل البيانات، يعدلها (مثل ضغط gzip أو تشفير AES)، ثم يخرجها كبيانات جديدة.

Predict Before You Run · توقّع النتيجة أولاً

What happens if a Readable stream pushes data faster than the Writable stream can write to disk?

ماذا يحدث إذا كان تدفق القراءة يضخ البيانات بسرعة أعلى من قدرة تدفق الكتابة على التخزين؟

يحدث Backpressure (ضغط عكسي)! يعيد الـ Writable إشارة false، مما يوقف القراءة مؤقتاً حتى يتم تفريغ الـ Buffer عبر حدث drain لتجنب امتلاء الذاكرة.

السطر 7: تدفق createGzip يضغط كل قطعة (Chunk) فور وصولها ويمررها مباشرة للقرص دون تخزين الملف في الـ RAM.

5. Deep Dive & Complexity Analysis · التحليل والتعقيد

Memory Complexity (RAM)
O(1) Bounded Buffer

تستهلك الـ Streams حجماً ثابتاً صغيراً في الذاكرة (افتراضياً 64KB للـ highWaterMark) بصرف النظر عن حجم الملف.

Time-To-First-Byte (TTFB)
Instant Streaming

يبدأ إرسال أول بايت للعميل فور قراءة أول Chunk دون انتظار اكتمال قراءة الملف بأكمله.

Why readable.pipe() is dangerous in Production

دالة readable.pipe(writable) القديمة لا تدير أخطاء الإغلاق التلقائي (Destruction) بشكل كامل إذا انقطع اتصال العميل في المنتصف، مما يسبب تسريبات ذاكرة (Memory Leaks). لذلك يوصى دائماً باستخدام stream.pipeline الحديثة التي تضمن تنظيف كل التدفقات.

6. Practice & Common Mistakes · أخطاء شائعة

Buffering Entire Big File into RAM (Out-Of-Memory Crash)
// ❌ CRASHES ON 2GB FILE
const file = await fs.promises.readFile('huge.csv');
res.send(file);
// ✅ MEMORY SAFE (Constant 64KB RAM)
const stream = fs.createReadStream('huge.csv');
stream.pipe(res);

التشخيص: قراءة الملف ككتلة واحدة تجبر V8 على حجز 2GB من الـ Heap memory، مما يؤدي إلى انهيار العملية (JavaScript heap out of memory).
