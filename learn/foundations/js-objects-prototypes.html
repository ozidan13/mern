Objects, Property Descriptors & Prototype Inheritance

الكائنات، واصفات الخصائص (Property Descriptors) وسلسلة التوريث عبر الـ Prototype

🎯 المستوى: تأسيسي متقدم
⚡ الإصدار: ES2024+ Standard
📐 النمط: Prototypal Inheritance & Memory Sharing

🎯 مخرجات التعلم وأهداف الدرس

  • ✓ فهم نموذج التوريث القائم على الـ Prototype (Prototypal Inheritance) ومقارنته بالتوريث الكلاسيكي في اللغات الأخرى.
  • ✓ التحكم في خصائص الكائنات عبر Object.defineProperty و واصفات الخصائص (writable, enumerable, configurable).
  • ✓ تجميد الكائنات وحمايتها من التعديل عبر Object.freeze() و Object.seal().

الفكرة الأساسية وسياق العالم الحقيقي

لماذا نحتاج هذا المفهوم وكيف يحل مشاكل الإنتاج المعقدة؟

في لغات زي Java أو C++، التوريث مبني على الـ Classes كقوالب ثابتة تُبنى منها الكائنات. لكن في جافاسكريبت، الأمر مختلف تماماً: الكائنات ترث مباشرة من كائنات أخرى عن طريق رابط خفي اسمه الـ Prototype Chain! هل تساءلت يوماً: لما بتنشئ مصفوفة جديدة const arr = []، ميثود arr.push() و arr.map() بتيجي منين؟ هل كل مصفوفة بتاخد نسخة خاصة من الدوال دي في الذاكرة؟ بالتأكيد لا! كل مصفوفة تحمل رابطاً سرياً [[Prototype]] يشير إلى Array.prototype في الذاكرة المشتركة. فهم واصفات الخصائص (Property Descriptors) وسلسلة الـ Prototype هو المفتاح لحماية كائناتك من التعديلات الخبيثة، وبناء مكتبات برمجية خفيفة تستهلك أقل قدر ممكن من الـ RAM عن طريق مشاركة الدوال بدلاً من تكرارها.

📖 تشبيه واقعي من بيئة العمل الهندسية

إذا قام الخادم بدمج كائن خبيث يحتوي على الخاصية "__proto__" في كائن عام (Deep Merge)، سيتم تعديل Object.prototype الخاص بجميع الكائنات في التطبيق! هذا قد يؤدي لتجاوز فحوصات الصلاحيات (مثل isAdmin: true) على مستوى كل المستخدمين. الحل هو استخدام Map أو كائنات معزولة بـ Object.create(null) أو فحص المفاتيح المدخلة وتطهيرها.

الميكانيكا العميقة: كيف يعمل خطوة بخطوة؟

تشريح تفصيلي لآلية العمل ومراحل التنفيذ داخل المحرك

01

رابط التوريث الداخلي ([[Prototype]] vs prototype)

خاصية prototype توجد فقط على الدوال البانية (Constructor Functions)، بينما [[Prototype]] أو __proto__ هو الرابط الفعلي الموجود على كل كائن.

02

رحلة البحث في الـ Prototype Chain

عند قراءة خاصية من كائن، يبحث المحرك في الكائن نفسه؛ وإذا لم يجدها يصعد للـ Prototype الخاص به، ويستمر حتى يصل إلى Object.prototype ثم null.

03

واصفات الخصائص (Property Descriptors)

كل خاصية لها 3 أعلام: writable (هل يمكن تغيير قيمتها؟)، enumerable (هل تظهر في الحلقات؟)، و configurable (هل يمكن حذفها أو تغيير واصفاتها؟).

04

حماية الكائنات: Object.freeze مقابل Object.seal

Object.seal تمنع إضافة أو حذف الخصائص ولكن تسمح بتعديل القيم الحالية. Object.freeze تجعل الكائن غير قابل للتعديل تماماً (Shallow Immutability).

05

إنشاء كائنات بدون Prototype (Object.create(null))

إنشاء قواميس بيانات فائقة النقاء لا ترث خصائص Object.prototype لمنع هجمات Prototype Pollution.

CODE SNIPPET الشرح الهندسي والدلالة
const proto = { greet() { return `Hi, ${this.name}`; } }; كائن الأساس المشترك
const user = Object.create(proto); إنشاء كائن جديد يرث من proto مباشرة
user.name = "Farah"; خاصية خاصة بالكائن user
console.log(user.greet()); // "Hi, Farah" تنفيذ ميثود greet الموروثة من الـ prototype
Object.freeze(user); تجميد الكائن لمنع التعديل والإضافة
console.log(Object.isFrozen(user)); // true التحقق من حالة التجميد

أخطاء الإنتاج القاتلة مقابل أفضل الممارسات

مقارنة بصرية واضحة بين الكود الكارثي والكود الهندسي المعتمد

🚨 الكود الخاطئ / Anti-Pattern 
// خطأ شائع: تعديل الـ Native Prototypes مباشرة (Monkey Patching)
Array.prototype.last = function() {
  return this[this.length - 1];
}; // كارثة: يسبب تصادم مع مكاتب أخرى ومعايير جافاسكريبت المستقبلية!
✨ الكود الهندسي المعتمد / Best Practice 
// الحل الهندسي: استخدام دوال مساعدة مستقلة أو ميثودز قياسية حديثة
function getLastItem(array) {
  return array.at(-1); // ES2022 Native Standard Method
}

سؤال إنترفيو للمهندسين الكبار: هل دالة Object.freeze() تقوم بتجميد عميق (Deep Freeze) للكائنات المتداخلة؟ وكيف تنفذ Deep Freeze آمن؟

دالة Object.freeze() تنفذ تجميداً سطحياً فقط (Shallow Freeze). هذا يعني أنه إذا كان الكائن يحتوي على كائن فرعي، فإن الكائن الفرعي يظل قابلاً للتعديل! لتنفيذ Deep Freeze آمن، يجب كتابة دالة تفحص كل خاصية تكرارياً (Recursively)، فإذا كانت كائناً غير مجمد يتم استدعاء Object.freeze عليها، مع تجنب الدخول في دوائر مرجعية (Circular References) باستخدام WeakSet.
