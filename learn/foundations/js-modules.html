ES Modules (ESM) vs CommonJS (CJS), Tree-Shaking & Dynamic Imports

أنظمة الحزم: ES Modules مقابل CommonJS والتحميل الديناميكي

🎯 الأهداف الهندسية لهذا الدرس (Learning Objectives)

  • فهم الفروق الجوهرية بين التحميل المتزامن في CJS والتحليل الثابت (Static Analysis) في ESM.
  • إتقان التصدير المسمى (Named Exports) مقابل التصدير الافتراضي (Default Export).
  • تطبيق الاستيراد الديناميكي import() لتقسيم الكود (Code Splitting) وتحسين سرعة التحميل.

المشكلة الهندسية والسياق الواقعي

رؤية الواقع العملي · Real-World Context & Mental Model

عالم جافاسكربت كان مقسوماً لسنوات بين نظام CommonJS المستخدم في بيئة Node.js التقليدية (require و module.exports) ونظام ES Modules المعياري الحديث للمتصفحات والباك إند (import و export). الخلط بين النظامين يسبب أخطاء شهيرة مثل ERR_REQUIRE_ESM، والأهم أن CJS نظام تحميل ديناميكي متزامن يمنع أدوات الحزم من حذف الأكواد غير المستخدمة (Tree-Shaking).

كيف تعمل المنظومة خطوة بخطوة · Mechanics & Execution

1
التحليل الثابت وميزة Tree-Shaking

في ESM، جمل الاستيراد تكون في أعلى الملف وتُحلل قبل التشغيل مما يسمح بحذف أي دالة لا يتم استخدامها.

2
الاستيراد الديناميكي (Dynamic Import)

استدعاء import("./module.js") كدالة تُرجع Promise لتحميل الكود عند الحاجة فقط (On-Demand).

3
التوافق في Node.js الحديث

ضبط "type": "module" في package.json لتفعيل نظام ESM القياسي في كل ملفات المشروع.

تحدي التوقع قبل التشغيل · Predict Before You Run

🤔 سؤال تحدي المهندسين:

لماذا لا يمكنك استخدام require() داخل ملف تم تعريفه كـ ES Module في Node.js؟

اضغط هنا للكشف عن الإجابة والتحليل الهندسي الدقيق

لأن نظام ESM يعمل ببيئة معزولة ولا يحتوي على متغيرات CJS العامة (require, __dirname, __filename)؛ في ESM نستخدم import/export المعياري أو createRequire من مكتبة node:module.

تشريح الكود سطراً بسطر · Code Anatomy

1: // Named Export (Tree-Shakeable)                // تصدير دوال محددة بالاسم
2: export const calculateTax = (amount) => amount * 0.14; // تصدير الدالة
3: // Dynamic Import (Code-Splitting)              // تحميل عند الطلب
4: const { calculateTax } = await import("./tax.js"); // استيراد ديناميكي معزول

معرض الأخطاء الشائعة والحل النموذجي · Mistakes Gallery

❌ الكود الخاطئ المسبب للكوارث (Anti-Pattern)
export default { fn1, fn2, fn3 }; /* يمنع الـ Bundler من حذف الدوال غير المستخدمة */
✅ الحل الهندسي الصحيح (Best Practice)
export const fn1 = ...; export const fn2 = ...; /* تصدير مسمى يتيح Tree-Shaking مثالي */

التشخيص الهندسي: تصدير كائن ضخم كـ default export يجبر المشروع على تحميل كل ما بداخل الكائن حتى لو احتجت دالة واحدة.

💬 سؤال إنترفيو للمهندسين الكبار (Senior Interview Q&A): كيف تحل مشكلة غياب __dirname و __filename عند العمل بنظام ES Modules في Node.js؟

نستخدم دالة `fileURLToPath` مع `import.meta.url` المدمجة في ESM كالتالي: `const __filename = fileURLToPath(import.meta.url); const __dirname = path.dirname(__filename);`.
