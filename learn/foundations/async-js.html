1. القصة والتشبيه الواقعي · The Core Story

تشبيه كاشير المطعم الذكي وجهاز التنبيه اللاسلكي · Fast Food Pager Buzzer

لو دخلت مطعم برجر ولقيت كاشير واحد بس شغال.. لو كان الكاشير شغال بنظام التزامن المباشر (Synchronous Blocking)، كان هيطلب منك الأوردر ويفضل واقف قصادك 10 دقائق يستنى الشيف يشوي اللحمة، والشارع كله واقف وراك في طابور مشلول!
لكن اللي بيحصل في الحقيقة هو نظام Asynchronous Event Loop: الكاشير بياخد طلبك في ثانية، يديك جهاز تنبيه صغير (Promise Pager)، ويقولك: "اتفضل استريح على الترابيزة.. ولما الأوردر يجهز الجهاز هيرن (Resolve)".. وفوراً يستقبل الزبون اللي بعدك في ثانية بدون أي تأخير!

المشكلة التي حلتها الـ Promises و Async/Await

زمان في جافاسكربت، عشان تعمل 3 طلبات ورا بعض (مثلاً تجيب المستخدم، ثم تجيب مقالاته، ثم تجيب التعليقات)، كنت بتضطر تحط دالة استدعاء جوه دالة استدعاء جوه دالة استدعاء، وده عمل كابوس هرمي مشهور اسمه Callback Hell أو Pyramid of Doom كان مستحيل قراءته أو معالجة أخطائه. الـ Promises ثم Async/Await حولت الكود لشكل خطي متسلسل سهل القراءة كأنه كود متزامن عادي مع استخدام try...catch النظيفة!

3. سحب مهمة من طابور الـ Macrotasks (Task Queue)

بعد تفريغ كل الـ Microtasks بالكامل وتحديث الـ UI Rendering، تسحب حلقة الـ Event Loop مهمة واحدة فقط من طابور المؤقتات (setTimeout / setInterval) وتعيد الدورة.

توقّع النتيجة أولاً · Predict Before You Run

إيه هو الترتيب الصحيح للأرقام المطبوعة في هذا الكود؟ 

console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
console.log('4');

الترتيب هو: 1 ← 4 ← 3 ← 2
- 1 و 4: كود متزامن ينفذ فوراً في الـ Call Stack.
- 3: Promise في طابور الـ Microtask وله الأولوية القصوى.
- 2: setTimeout في طابور الـ Macrotask وينفذ بعد تفريغ كل الوعود.

5. تشريح دالة الـ Async/Await الحديثة · Code Anatomy

1: async function loadUserProfile(userId) { 2: try { 3: const res = await fetch(`/api/users/${userId}`); 4: if (!res.ok) throw new Error(`HTTP Error: ${res.status}`); 5: return await res.json(); 6: } catch (err) { 7: console.error('Failed to fetch user:', err.message); 8: } 9: }

السطر 1: كلمة async تجعل الدالة تعيد Promise تلقائياً وتسمح باستخدام await بداخلها.

السطر 3: كلمة await توقف تنفيذ هذه الدالة فقط مؤقتاً وتترك باقي التطبيق يعمل بسلاسة حتى يكتمل الطلب.

السطر 6: كتلة catch تلتقط أخطاء الشبكة والوعود المرفوضة في مكان مركزي واحد.

6. كواليس هندسية وتحليل الأداء · Deep Dive

التنفيذ بالتوازي (Parallel Execution)
Promise.all()

بدل انتظار الطلبات بالتتالي (Waterfall)، استخدام Promise.all([p1, p2]) يطلق كل الطلبات بالتوازي ويختصر زمن الاستجابة إلى زمن أبطأ طلب فقط!

أمان الوعود المتعددة
Promise.allSettled()

تضمن استلام نتائج جميع الوعود حتى لو فشل بعضها، على عكس Promise.all التي تنهار فوراً عند أول فشل (Short-circuit).

7. أخطاء شائعة وفخاخ يقع فيها الجميع · Common Pitfalls

فخ الـ Waterfall البطيء داخل الحلقات
// ❌ بطيء جداً: ينتظر كل طلب حتى يكتمل قبل بدء التالي (3000ms)
for (const id of userIds) {
  await fetchUser(id);
}
// ✅ سريع جداً: إطلاق كل الطلبات بالتوازي (1000ms فقط)
const promises = userIds.map(id => fetchUser(id));
await Promise.all(promises);

التشخيص الهندسي: استخدام await داخل حلقة for يجبر الشبكة على الانتظار التتابعي، بينما Promise.all يستغل الـ Multiplexing ويطلق الطلبات معاً.

قاموس المصطلحات الأساسية · Mini-Glossary

Event Loop
محرك المراقبة الدائري المسؤول عن مراقبة الـ Call Stack وسحب المهام الجاهزة من طوابير الـ Microtasks والـ Macrotasks فور فراغ المكدس.
Promise
كائن يمثل القيمة المستقبلية لعملية غير متزامنة قد تكتمل بنجاح (Resolved) أو تفشل بخطأ (Rejected).

9. في بيئة العمل والمقابلات التقنية · Production & Interviews

سؤال مقابلات شهير: إيه الفرق بين Promise.all و Promise.race و Promise.any؟

الإجابة الهندسية:
- Promise.all: ينتظر نجاح الجميع، ويفشل فوراً لو فشل واحد بس.
- Promise.race: يعيد نتيجة أول وعد ينتهي (سواء نجح أو فشل).
- Promise.any: يعيد نتيجة أول وعد ينجح، ويتجاهل الأخطاء حتى تفشل كل الوعود معاً.
