How the Web & HTTP/3 Work

1. Core Concept & Mechanics · الفكرة الأساسية

Real-Life Analogy · تشبيه خدمة البريد السريع وقفل الأمان

عندما تكتب عنوان موقع (مثل google.com)، الأمر يشبه إرسال رسالة لشخص لا تعرف سوى اسمه: أولاً تبحث في دليل الهاتف (DNS) لتحصل على رقم منزله الحقيقي (IP Address). ثم يذهب ساعي البريد ليصافح الحارس عند الباب ويتبادلا شفرة سرية مشفرة (TLS Handshake) لضمان ألا يقرأ الرسالة أحد في الطريق. في السابق، كان الساعي ينتظر توصيل كل ظرف واحداً تلو الآخر في طابور طويل (HTTP/1.1). أما في HTTP/3، فقد أصبح لدينا أسطول من الطائرات المسيرة السريعة المستقلة (QUIC preko UDP) التي لا تتعطل إذا تعثرت واحدة منها!

Definition & Purpose

The Web operates on a client-server architecture powered by the Internet Protocol Suite. When a user requests a URL, the browser resolves the host IP via DNS, establishes an encrypted transport session (TCP/TLS or QUIC), exchanges HTTP requests/responses, and parses HTML/CSS/JS into the Render Tree.

يعتمد الويب على نموذج العميل والخادم (Client-Server Architecture). عند طلب أي صفحة، يمر الطلب بسلسلة محددة من البروتوكولات تبدأ من ترجمة اسم النطاق إلى عنوان رقمي عبر DNS، ثم فتح قناة مشفرة آمنة، ثم تبادل رسائل بروتوكول نقل النص الفائق (HTTP) حتى يستقبل المتصفح حزم البيانات ويحولها إلى واجهة مرئية.

Why HTTP/3 Exists · لماذا انتقلنا إلى HTTP/3 و QUIC؟

في بروتوكول TCP التقليدي، إذا ضاعت حزمة بيانات واحدة أثناء النقل بسبب ضعف الشبكة، يتوقف الطابور بالكامل حتى يُعاد إرسال تلك الحزمة وتأكيدها (ظاهرة تعرف بـ Head-of-Line Blocking). يحل بروتوكول HTTP/3 المبني على UDP / QUIC هذه المشكلة بنقل كل مسار بشكل مستقل تماماً بدون تأخير للمسارات الأخرى.

Step-by-Step Mechanics · المراحل الأربع لرحلة الطلب

1
1. DNS Resolution (دليل العناوين)

المتصفح يفحص الـ Cache المحلي، ثم يسأل خوادم DNS للوصول إلى الـ IP الحقيقي للسيرفر (مثل 142.250.190.46).

2
2. Connection & TLS 1.3 Handshake (المصافحة والتشفير)

تبادل مفاتيح التشفير عبر TLS لضمان سرية البيانات وتوثيق هوية الخادم بشهادة SSL/TLS.

3
3. HTTP Request & Response (تبادل البيانات)

إرسال رأس الطلب (Headers) وجسم الطلب (Body)، ثم استلام الـ Status Code (مثل 200 OK) والمحتوى المطلوب.

4
4. Critical Rendering Path (بناء الواجهة والـ DOM)

محرك المتصفح يحلل HTML لبناء الـ DOM، ويحلل CSS لبناء CSSOM، ثم يدمجهما في Render Tree لحساب التخطيط والرسم (Paint).

4. Code Anatomy · تشريح رسالة الـ HTTP

Hover over each line to examine raw HTTP/1.1 and HTTP/2 frame anatomy:

1: GET /api/v1/users HTTP/1.1 2: Host: api.fullstack.academy 3: User-Agent: Mozilla/5.0 4: Accept: application/json 5: Authorization: Bearer eyJhbGciOi...

السطر 1 (Request Line): يحدد نوع الفعل (GET)، المسار المطلوب (/api/v1/users)، وإصدار البروتوكول.

السطر 2 (Host Header): إلزامي في HTTP/1.1 لتحديد الخادم المستهدف في السيرفرات المشتركة (Virtual Hosting).

السطر 4 (Accept): يخبر الخادم بنوع البيانات التي ينتظرها العميل (مثل JSON).

5. Deep Dive & Complexity Analysis · التحليل والتعقيد

DNS Resolution Cost
O(1) Cached

بمجرد حفظ الـ IP في كاش المتصفح أو نظام التشغيل (TTL)، تصبح استجابة الـ DNS شبه لحظية.

HTTP/3 Handshake Latency
1-RTT / 0-RTT

يدمج بروتوكول QUIC مصافحة الاتصال مع مصافحة التشفير TLS 1.3 في دورة واحدة (1-RTT) أو صفرية (0-RTT).

Protocol Evolution: HTTP/1.1 vs HTTP/2 vs HTTP/3
Protocol Transport Multiplexing Head-of-Line Blocking
HTTP/1.1 TCP No (Pipelining flawed) Application & Transport
HTTP/2 TCP Yes (Binary Frames) Transport TCP level only
HTTP/3 UDP (QUIC) Yes (Independent Streams) None (Completely eliminated)

Mini-Glossary · قاموس المصطلحات

DNS (Domain Name System)
نظام أسماء النطاقات المسؤول عن تحويل الأسماء النصية (مثل example.com) إلى عناوين IP رقمية.
TLS (Transport Layer Security)
بروتوكول تشفير يوفر السرية وسلامة البيانات بين العميل والخادم عبر شهادات الأمان.
QUIC Protocol
بروتوكول نقل حديث يعتمد على UDP تم تصميمه لتقليل زمن التأخير وتجنب تعطل المسارات المتعددة.

8. Production Notes & Interviews · في بيئة العمل والمقابلات

Senior Web Architecture Interview Questions

Q: What happens from the moment you type "https://google.com" into the address bar until the page is fully rendered?

الإجابة المتكاملة:
1. تحليل الـ URL واستخراج البروتوكول والمضيف.
2. فحص الـ DNS Cache وحل الـ IP عبر الـ Recursive Resolver.
3. فتح اتصال المصافحة (TCP Handshake + TLS 1.3 أو QUIC).
4. إرسال طلب HTTP GET واستقبال أول بايت (TTFB).
5. تحليل الـ HTML وبناء شجرة الـ DOM والـ CSSOM.
6. تنفيذ JavaScript واكتمال مسار العرض (Critical Rendering Path).
