How the Web Works: HTTP/3 & DNS Lifecycle

أهداف الدرس ونقاط الإتقان · Learning Objectives

1. القصة والتشبيه الواقعي · The Core Story

تشبيه دليل الهاتف ومأمور الشحن السريع · Phonebook & Courier

تخيل إنك عايز تطلب أكل دليفري من مطعم مشهور اسمه "البرجر الملكي". أنت في دماغك حافظ الاسم، لكن الموبايل والشبكة ميعرفوش يوصلوا بالاسم.. لازم رقم التليفون أو العنوان الجغرافي بالأرقام! أول خطوة: بتفتح دليل الهاتف السريع (DNS Resolution) عشان يقولك: البرجر الملكي عنوانه الجغرافي هو 142.250.190.46.
ثاني خطوة: بتتصل بيه وتتفقوا على شفرة سرية عشان محدش يتجسس على تفاصيل الدفع (TLS 1.3 Handshake).
ثالث خطوة: بتبعت طيار الدليفري السريع (HTTP/3 QUIC Streams) يجيبلك السندوتش والبطاطس والبيبسي مع بعض في نفس الوقت بدون ما لو عجلة الموتوسيكل فرقعت يوقف كل الطلبات الباقية!

المشكلة الهندسية التي حلتها البروتوكولات الحديثة

في بدايات الويب مع بروتوكول HTTP/1.1، كان المتصفح عشان يحمل 50 صورة في الصفحة لازم يفتح لكل صورة اتصال TCP منفصل، أو يستنى الصورة الأولى تخلص عشان يبدأ في التانية، وده كان بيعمل اختناق كابوسي اسمه Head-of-Line Blocking. مع HTTP/2 بدأنا نبعت كذا ملف على نفس الاتصال (Multiplexing)، لكن كانت المشكلة لو باقة إنترنت واحدة ضاعت على شبكة TCP، الاتصال كله بيقف في إشارة مرور! هنا بقى ظهرت الثورة الحقيقية مع HTTP/3 المعتمد على QUIC بروتوكول عبر UDP، اللي خلى كل Stream مستقل تماماً وسريع زي الصاروخ حتى لو شبكة الموبايل بتقطع!

2. رحلة الـ Request خطوة بخطوة · Step-by-Step Mechanics

1
1. استخراج الـ IP من دليل النطاقات (DNS Resolution)

المتصفح بيبص أولاً في الـ Cache المحلي، لو ملقاش الـ IP بيسأل الـ Recursive Resolver، اللي بيسأل سيرفرات الـ Root (.)، ثم سيرفرات الـ TLD (.com)، لحد ما يوصل للـ Authoritative Server وياخد الـ IP النهائي.

2
2. إنشاء القناة الآمنة (QUIC + TLS 1.3 0-RTT Handshake)

بدل تضييع 3 رحلات رايح جاي (3-way handshake) في TCP القديم، بروتوكول QUIC بينشئ الاتصال ويتبادل مفاتيح التشفير في رحلة واحدة (1-RTT) أو فورياً لو زرت الموقع قبل كده (0-RTT).

3
3. تبادل الـ HTTP Streams ومعالجة السيرفر

المتصفح بيبعت طلب GET /index.html مع الـ Headers، السيرفر (Node.js / Nginx) بيعالج الطلب ويرجع كود الحالة 200 OK وتدفق الـ HTML.

5. تشريح رسالة الـ HTTP الخام · Request Anatomy

1: GET /api/v1/users?page=2 HTTP/3 2: Host: api.fullstack.academy 3: User-Agent: Mozilla/5.0 Chrome/128.0 4: Accept: application/json 5: Authorization: Bearer eyJhbGciOi...

السطر 1 (Request Line): بيحدد نوع الفعل GET، مسار المورد المطلوب، وإصدار البروتوكول.

السطر 2 (Host Header): إجباري عشان السيرفر يقدر يعرف أنت بتطلب أنهي موقع لو السيرفر مستضيف كذا دومين على نفس الـ IP (Virtual Hosting).

السطر 5 (Auth Token): تمرير رمز التوثيق المشفر للتحقق من هوية المستخدم في كل طلب.

6. كواليس هندسية وتحليل الأداء · Deep Dive

زمن الاتصال (Connection Latency)
0-RTT vs 3-RTT

بروتوكول HTTP/3 يقلل زمن إعداد الاتصال الأولي بنسبة تصل إلى 65% مقارنة بـ TCP القديم، خصوصاً على شبكات المحمول اللاسلكية.

كاش الـ DNS الهرمي
O(1) Local Cache Hit

90% من استعلامات الـ DNS لا تسافر عبر الإنترنت، بل تُحل محلياً في 0ms من ذاكرة المتصفح أو نظام التشغيل (OS Resolver Cache).

قاموس المصطلحات الأساسية · Mini-Glossary

DNS (Domain Name System)
نظام التسمية الموزع عالمياً المسؤول عن تحويل الأسماء المفهومة للبشر (مثل google.com) إلى عناوين IP رقمية تفهمها أجهزة الراوتر.
TLS 1.3 (Transport Layer Security)
أحدث بروتوكول تشفير للويب يضمن سرية البيانات وسلامتها بين المتصفح والخادم مع تقليل خطوات المصافحة لتسريع الأداء.

9. في بيئة العمل والمقابلات التقنية · Production & Interviews

سؤال مقابلات شهير: إيه الفرق بين 127.0.0.1 و 0.0.0.0 عند تشغيل السيرفر؟

الإجابة الهندسية:
- عنوان 127.0.0.1 (Loopback / Localhost): يعني أن السيرفر يستمع فقط للطلبات القادمة من نفس جهازك الداخلي، ولن يستطيع أي جهاز آخر على شبكة الـ Wi-Fi الوصول إليه.
- عنوان 0.0.0.0 (All Interfaces / Wildcard): يعني أن السيرفر يستمع على جميع كروت الشبكة المتاحة في الجهاز، مما يسمح للأجهزة الأخرى في الشبكة أو حاويات Docker بالاتصال به مباشرة.
