JS Execution Context, Scope & Closures

إزاي محرك V8 بيشغل الكود في الذاكرة؟ أسرار الـ Call Stack، الـ Hoisting، والـ Closures

التقنيات: V8 Engine · Execution Context · Closures المستوى 1 30 دقيقة
أهداف الدرس ونقاط الإتقان · Learning Objectives
  • فهم المرحلتين السحريتين لأي كود في جافاسكربت: مرحلة حجز الذاكرة (Memory Creation) ثم مرحلة التنفيذ (Execution).
  • تتبع مكدس الاستدعاءات (Call Stack LIFO) وكيف تحدث كارثة الـ Stack Overflow.
  • إتقان مفهوم الـ Closures ونطاق المتغيرات المعجمي (Lexical Scope) كأهم سلاح في الـ Full-Stack.

1. القصة والتشبيه الواقعي · The Core Story

تشبيه الطباخ المساعد وحقيبة الظهر السحرية · Chef & The Magic Backpack

تخيل إن محرك V8 شغال زي رئيس طهاة في مطعم عالمي: قبل ما يولع النار حتى، بيمسك المنيو ويجهز الأطباق والمكونات على الرخامة في مرحلة أولى اسمها (Creation Phase).
بعد كده، بيبدأ يطبخ الأطباق طبق ورا طبق ويرصهم فوق بعض في مكدس (Call Stack): الطبق اللي بيتحط على الوش هو أول واحد بيخلص ويخرج (LIFO)!
أما الـ Closure: فتخيل إن كل دالة داخلية بتتولد في المطبخ، بتاخد معاها حقيبة ظهر سحرية (Backpack) فيها كل المكونات والبهارات بتاعة الدالة الأب، وحتى لو الدالة الأب خلصت وماتت وخرجت من المطبخ.. تفضل الدالة الابنة محتفظة بالحقيبة وتستخدم متغيرات الأب في أي وقت في المستقبل!

المشكلة التي حلتها الـ Closures في عالم البرمجة

زمان، لما كنت بتعوز تعمل دالة تعدّاد (Counter) أو تحتفظ بحالة خاصة (Private State)، كنت بتضطر تعمل متغير عام (Global Variable) في الملف كله، وأي جزء في التطبيق كان ممكن يغيره بالغلط ويبوظ الدنيا. مع الـ Closures، بقيت تقدر تعمل Encapsulation حقيقي وتخفي المتغيرات داخل دالة، وتصدر فقط دوال التحكم (زي فكرة الـ useState في React تماماً)!

2. كواليس تشغيل الكود في الذاكرة · Execution Context Phases

1
1. مرحلة إنشاء السياق (Creation / Hoisting Phase)

محرك V8 يمسح الكود سطر سطر: يحجز مكان للدوال الكاملة في الذاكرة، ويحجز مكان لمتغيرات var بقيمة مبدئية undefined، بينما يضع متغيرات let و const في المنطقة الزمنية الميتة (Temporal Dead Zone - TDZ).

2
2. مرحلة التنفيذ الفعلي (Execution Phase)

يتم تشغيل الكود سطراً بسطر وحساب القيم، وعند استدعاء أي دالة يتم إنشاء (Function Execution Context) جديد ودفعه فوراً إلى قمة الـ Call Stack.

3
3. الاحتفاظ بالنطاق الحي (Closure Formation)

إذا أعادت الدالة دالة فرعية بداخلها، تظل المتغيرات المشار إليها محفوظة في الـ Heap Memory ولا يمسها الـ Garbage Collector لأن مرجع الـ Closure ما زال حياً!

توقّع النتيجة أولاً · Predict Before You Run

إيه اللي هيطبع في الـ Console لما نشغل الكود ده؟ 

console.log(a);
var a = 10;
console.log(b);
let b = 20;

السطر الأول يطبع: undefined (بسبب رفع var في الـ Hoisting).
السطر الثالث يرمي استثناء: ReferenceError: Cannot access 'b' before initialization لأن let موجودة في المنطقة الزمنية الميتة (TDZ).

5. تشريح دالة الـ Closure الاحترافية · Code Anatomy

1: function createWallet(initialBalance) { 2: let balance = initialBalance; // Private state 3: return { 4: deposit: (amount) => { balance += amount; return balance; }, 5: getBalance: () => balance 6: }; 7: }

السطر 2: متغير balance محبوس داخل النطاق المحلي لدالة createWallet ومستحيل الوصول له من الخارج.

السطر 4 & 5: دوال الـ Arrow المعادة تحتفظ برابط مباشر (Closure Reference) إلى balance حتى بعد انتهاء تنفيذ الدالة الأب.

6. كواليس هندسية وتحليل الأداء · Deep Dive

كفاءة الـ Call Stack
O(1) Push / Pop

عمليات إضافة وحذف سياق الدوال في الـ Stack تتم بزمن فوري O(1) مباشر وسريع جداً في لغة الآلة.

استهلاك الذاكرة (Memory Leaks)
Heap Retention

الـ Closures تمنع محرك الـ Garbage Collector من تنظيف المتغيرات، لذلك ترك مراجع غير مستخدمة قد يؤدي لتسريب الذاكرة (Memory Leak).

7. أخطاء شائعة وفخاخ يقع فيها الجميع · Common Pitfalls

فخ الـ var داخل حلقات التكرار (Loop Closure Trap)
// ❌ يطبع 3 ثلاث مرات!
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// ✅ يطبع 0 ثم 1 ثم 2 بشكل سليم
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}

التشخيص الهندسي: استخدام var يشارك نفس المتغير عبر كل التكرارات، بينما let تنشئ نطاق كتلة جديد (Block Scope) لكل لفة في الـ Loop فيتذكره الـ Closure بدقة.

Closure
